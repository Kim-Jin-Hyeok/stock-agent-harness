# 일봉 거래대금 원천 의미 검증 결과 01

## 판정과 범위

2026-10-03 공개 KIS 명세와 공식 예제를 열람하고, [보충 실측 02](daily-price-trading-value-backfill-observation-02.md)에 보존된 삼성전자 `005930`의 3일 응답을 읽었다. **필드와 요청 인자의 의미는 확인했으나, 원 단위 배율과 정확한 세션 집계 범위의 검증은 완료하지 못했다.** 같은 종목·날짜·시장·세션 범위의 독립적인 공식 수치 대조도 수행하지 못했다.

이 문서는 확인한 근거와 부족한 근거를 구분하는 조사 결과다. 실제 보충의 성공을 취소하는 것도, 거래대금의 유동성 사용을 승인하는 것도 아니다. 단위나 집계 범위를 잘못 가정하면 유동성 최소 기준과 후보 순위가 달라질 수 있으므로, 숫자가 그럴듯하다는 이유로 검증 게이트를 통과시키지 않는다.

이번 작업은 기존 파일 읽기와 공개 문서 열람만 수행했다. DB 연결·변경, Docker 조작, KIS 토큰 발급·시세 조회·주문 호출은 하지 않았다. Java·설정·마이그레이션·원본 증거도 변경하지 않았다. 기준 코드는 `bf518acd0bb2c2a95f9f4db2ce9ce2d9295bcb3f`다.

## 저장 경로와 확인 수준

현재 `com.stock.market.price.history.provider.kis.dto.KisDailyPriceBarOutput`은 `output2.acml_tr_pbmn`을 `Long` 정수로 해석한다. 금액 배율을 곱하지 않고 `DailyPriceBar.tradingValueKrw`로 전달한다. 필드 누락·null·공백은 미확인 값으로 보존하며 종가와 거래량을 곱해 대체하지 않는다.

`KisDailyPriceHistoryClient`는 일봉과 수정주가 인자를 사용하고, `KisDailyPriceHistoryMarket`의 요청 코드에 대응하는 `TradingVenueScope`를 전달한다. 저장된 `INTEGRATED`는 **실제 요청한 통합 조회 범위**를 나타내며, 응답의 정확한 세션 구성을 별도로 입증하는 필드가 아니다.

## 보존 응답의 제한된 산술 점검

사용한 파일은 Git에서 제외되는 `build/trading-value-backfill-observation-02/chart-response.json`이다. 이번 읽기 후 SHA-256은 기존 기록과 같았다.

`3FFF202DBE1B2F4B340B4B74367546713949A7820E7C3BEE3544AC200F8DF132`

응답 보존 시각은 `2026-10-03T02:31:51.560008800Z`이며 KST로 11:31:51이다. 모의투자 조회의 요청 기간은 `2026-09-21~23`, 시장은 `UN`, 주기는 `D`, 가격 인자는 `0`이었다. 새 응답을 조회하거나 파일을 다시 생성하지 않았다.

| 날짜 | 원문 거래대금 정수 | 원문 거래량 | 원문 정수 / 거래량 | 응답 저가 ~ 고가 |
| --- | ---: | ---: | ---: | --- |
| 2026-09-21 | 9208918133058 | 33914657 | 271532.102862 | 259500 ~ 275000 |
| 2026-09-22 | 8743631121850 | 31323214 | 279142.208135 | 271500 ~ 283500 |
| 2026-09-23 | 9100552358490 | 32046681 | 283977.999422 | 280750 ~ 286500 |

계산에는 보존된 문자열을 PowerShell `decimal`로 변환했고 표시용 비율만 소수 여섯 자리로 반올림했다. 원문 정수·저장값·후보 기준은 반올림하거나 수정하지 않았다.

**조건부 추론:** 가격·거래량·거래대금의 시장·세션·조정 기준이 같고 거래대금이 원 단위라고 가정하면, 세 날짜 모두 나눗셈 결과가 응답 저가와 고가 사이에 있다. 이 표본은 배율 1이라는 가정과 산술적으로 모순되지 않는다.

하지만 같은 응답 안의 수치를 비교했을 뿐 독립 검증이 아니다. 이 비율을 공식 VWAP로 명명하거나, 원 단위·시간외 포함이 확인됐다고 결론내리지 않는다. 수정주가와 원 거래량·대금의 기준이 다를 수 있으므로 저가·고가 범위 검사를 모든 과거 일봉에 강제하는 운영 검증 규칙으로 추가하지 않는다.

각 행의 `flng_cls_code`, `prtt_rate`, `mod_yn` 값만으로 기업행위 이력이나 세션 확정을 검증하지 않는다. 보존 응답에는 날짜별 거래소·세션 상세 구성이 없어 이 파일만으로 KRX와 NXT를 분해할 수도 없다.

## 부족한 증거와 유한한 후속 확인

이번 공개 조사에서 확보하지 못한 자료는 다음과 같다. **필드 의미 확인과 수치 대조를 모두 마치기 전에는 평균 거래대금 후보 선정의 검증 완료로 처리하지 않는다.**

1. 이 API의 **일별 배열 필드**를 대상으로 통화와 숫자 1의 금액 단위, `J`·`NX`·`UN`별 포함 세션, 수정주가 선택 시 거래량·거래대금의 처리, 과거 일봉의 확정·정정 정책을 설명하는 공식 규격 또는 KIS 답변.
2. `005930`, `2026-09-21~23`의 날짜별 공식 거래대금과 그 자료의 시장·세션·단위·가격 조정 기준. 같은 통합 범위 자료 또는 호환성이 명시된 거래소별 상세 자료가 필요하다.

추가 공개 검색이나 Broker 조회를 무한 반복하지 않는다. 후속 범위는 위 자료를 받을 때 **이번 세 날짜만 다시 대조하는 한 번의 검증**으로 제한한다. 자료가 없으면 미확인 상태를 유지하고 유동성 기반 Universe 실행은 보류한다. KIS 문의가 필요하면 사용자가 제출할 질문에 위 확인 항목을 넣으며, 이 작업에서 문의를 전송하거나 자격 증명을 제공하지 않았다.

공식 비교값을 확보하면 날짜별로 `원문 정수 × 확인된 배율`과 공식 금액을 비교하고 원문·단위·범위·조회 또는 제공 시각·해시를 남긴다. 반올림된 표시 금액만 제공된다면 먼저 원자료 정밀도와 허용 오차를 고정한다. 결과를 맞추려고 사후에 배율이나 오차를 선택하지 않는다.

KRX 전용 통계를 `UN` 응답과 곧바로 비교하거나 `J + NX = UN`을 증명 없이 가정하지 않는다. 세션·집계 기준이 다르면 값의 차이를 파싱 오류로 확정하지 않고 비교 불가로 기록한다. 같은 기준임이 확인됐는데도 값이 다르면 원본을 보존하고 사용을 중단한다. 이번 표본의 검증이 끝나도 다른 날짜·기업행위·과거 정보 가용성까지 자동으로 확인된 것은 아니다.

## 유지하는 경계

원문 정수 보존, nullable 구분, 보충의 기존 값 충돌 보호와 조회 생략을 그대로 유지한다. 새로운 평균 계산·필터·종목 마스터·후보 선정 서비스는 만들지 않았다. 운영 후보·전략·Risk·스케줄과 주문 권한도 바꾸지 않았다.

[후보 Universe 계약](../../../../strategy/swing/validation/swing-v1-candidate-universe-contract.md)의 `DESIGN_ONLY`와 `runtimeSelectionImplemented=false`는 유지한다. 단위·집계 범위의 확인이 끝나더라도 과거 모집단·상장 유형·기업행위·시점 정보·선정 수치와 재현성 검증은 별도로 필요하다. 이번 결과를 전략 수익성이나 실제투자 준비 완료의 증거로 사용하지 않는다.

문서 변경만 있으므로 Java 테스트와 실측을 재실행하지 않았다. 상대 링크, 문서 차이의 공백 오류와 보존 응답 해시를 점검했다. 실행 절차는 [수동 보충 문서](../daily-price-trading-value-backfill.md), 실제 DB 변경·호출 결과는 [실측 02](daily-price-trading-value-backfill-observation-02.md)를 따른다.
