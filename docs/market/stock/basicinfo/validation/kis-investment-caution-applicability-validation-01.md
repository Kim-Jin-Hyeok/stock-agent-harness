# 시장별 투자주의환기 적용 범위 검증

2026-10-07 KST 기준, 현행 KRX 상장규정과 기존에 고정한 KIS 마스터 규격을 대조했다. **코스닥의 투자주의환기 지정 제도와 코스피의 원천 필드 부재를 동일한 정보 부족으로 처리하지 않을 근거를 확보했다.** 다만 원문 `null`을 `N`으로 보정하는 근거는 아니다. 원천 관측과 제도의 적용 여부는 별도로 기록해야 한다.

이번 변경은 근거와 후속 점검 기준을 정리하는 문서 작업이다. 현재 `KIS_STOCK_BASIC_INFO_RESTRICTION_SCREENING_V1`은 변경하지 않았으므로, [실환경 분석](kis-stock-basic-info-analysis-observation-01.md)의 `005930` 결과는 여전히 `REVIEW_REQUIRED`와 `MASTER_INVESTMENT_CAUTION_FIELD_NOT_PROVIDED`다. 아래 후속 판정 기준을 구현하거나 당시 결과에 소급 적용하지 않았다.

## 현행 규정과 시행일

공식 조회처는 [KRX 법무포털](https://rule.krx.co.kr/out/index.do)이다. 코스닥·유가증권시장 상장규정과 양 시장 시행세칙의 최신 항목을 열어 원문 표제와 부칙 시행일을 대조했다.

| 규정 | 고정 조회 bookid | 개정일 | 시행일 | 규정 번호 |
| --- | --- | --- | --- | --- |
| 코스닥시장 상장규정 | `330015704` | 2026-09-23 | 2026-09-23 | 제2510호 |
| 코스닥시장 상장규정 시행세칙 | `330020393` | 2026-10-02 | 2026-10-02 | 제2514호 |
| 유가증권시장 상장규정 | `330014540` | 2026-09-23 | 2026-09-23 | 제2506호 |
| 유가증권시장 상장규정 시행세칙 | `330020420` | 2026-10-02 | 2026-10-02 | 제2513호 |

개정일만으로 시행 여부를 추정하지 않았다. 위 시행일은 해당 버전 전체의 시행일이지 투자주의환기 제도의 최초 도입일이나 개별 종목의 지정일이 아니다. 제52조 본문의 개정 표시, 과거 부칙의 적용례와 최신 버전 시행일도 서로 다른 값이다.

구 `law.krx.co.kr` 법규서비스는 법무포털로의 개편과 12월 1일 이후 개정사항의 새 포털 조회를 안내한다. 검색되는 구 규정과 2024년 해설서는 현행 버전 확인의 대체 근거로 사용하지 않는다. [구 법규서비스 안내](https://law.krx.co.kr/las/main.jsp)

## 시장별 적용 근거

현행 코스닥 상장규정 제1조는 코스닥 상장증권과 상장법인의 관리를 규율한다. 제52조는 보통주식 상장법인의 투자주의환기 정기·수시 지정과 지정·해제 공표를 정한다. 시행세칙 제48조는 선정기준과 적용방법을 구체화하고, 별표 8과 9를 각각 선정기준과 지정·해제 시기에 연결한다. [보존한 규정 원문](../../../../../build/kis-investment-caution-applicability-validation-01/run-02/kosdaq-listing-rule.html), [보존한 시행세칙](../../../../../build/kis-investment-caution-applicability-validation-01/run-02/kosdaq-listing-enforcement.html)

수시 지정에는 회계·감사와 재무상태 외에 의무보유 위반이나 특정 자금거래 등의 사유도 있다. 단순 가격 급등 경보와 같지 않다. 또한 정기 선정의 제외 대상과 개별 사유의 적용 예외가 있으므로, 애플리케이션이 일부 재무비율만 계산해 거래소의 지정 여부를 만들어내지 않는다.

유가증권시장 상장규정 제1조의 대상은 유가증권시장이다. 고정한 규정과 시행세칙의 전체 원문·조문목록에는 같은 투자주의환기 지정 제도가 없었다. 코스닥 규정의 적용 시장, 양 시장 규정 대조와 KIS 규격 차이를 함께 근거로, **프로젝트의 코스피 보통주 점검에서는 이 제도의 비적용과 데이터 미확인을 구분하는 방향이 타당하다고 판단한다.** 코스피에 제한 종목이 없거나 거래가 항상 가능하다는 결론은 아니다. [보존한 유가증권시장 규정](../../../../../build/kis-investment-caution-applicability-validation-01/run-02/kospi-listing-rule.html), [보존한 시행세칙](../../../../../build/kis-investment-caution-applicability-validation-01/run-02/kospi-listing-enforcement.html)

[KRX 투자주의환기 지정 내역](https://data.krx.co.kr/contents/MDC/STAT/issue/MDCSTAT218.jsp)도 코스닥 구분으로 제공된다. 이 화면 명칭은 보조 근거이며, 명칭이나 코스피 필드 부재만으로 비적용을 확정한 것은 아니다.

적용 범위 판단은 이번에 확인한 버전과 프로젝트 대상인 KOSPI·KOSDAQ에 한정한다. KONEX·해외시장·다른 상품이나 모든 과거·미래 규정으로 확대하지 않는다. 우선주·ETF 등의 유형 제외와 개별 지정 사유의 예외도 이번 시장 구분으로 해소하지 않는다.

## 후속 점검 기준

원천 관측은 [현재 관측 규칙](../../master/kis-stock-trading-restriction.md)을 유지한다. 적용·비적용·적용 미확인은 별개의 정책 해석이며 `KisStockTradingFlagStatus`의 문자 관측을 대체하지 않는다.

아래는 **후속 버전에서 검증할 기준**이며 현재 V1의 동작 설명이 아니다. 식별 대조에 성공한 프로젝트 대상 종목을 전제로 하며, 다른 제한의 판정을 계속 함께 보존한다.

| 시장과 원문 | 보존 관측 | 후속 처리 기준 |
| --- | --- | --- |
| KOSPI, 고정 규격의 필드 부재 | `null` / `FIELD_NOT_PROVIDED` | 근거가 확인된 비적용으로 별도 기록한다. 이 한 항목만 검토 필요의 차단 사유에서 분리한다. |
| KOSDAQ, 정확한 `Y` | `Y_OBSERVED` | 제외 신호를 유지한다. |
| KOSDAQ, 정확한 `N` | `N_OBSERVED` | 해당 항목에 신호가 관측되지 않았다. 다른 검사 통과는 별도다. |
| KOSDAQ, 공백·소문자·미정의 문자 | `VALUE_UNVERIFIED` | 검토 필요를 유지한다. 시장 구분으로 면제하지 않는다. |
| KOSDAQ, 필드 자체 누락 | 현재 파서 계약 위반 | 유효한 N 관측이나 비적용으로 만들지 않고 기존 거절을 유지한다. |
| 시장·식별·규격·적용 근거 미확인 | 원래 입력과 진단 | 비적용을 만들지 않는다. 유효 입력의 점검은 검토 필요, 구조 위반은 기존 거절을 유지한다. |

같은 종목이라고 확인되지 않은 마스터와 API를 조합해서 시장 면제를 적용하지 않는다. 미래 코스피 규격에 필드가 생기거나 현재 계약과 다른 nonnull 값이 들어오면 현행 파서의 거절을 유지하고 새 규격부터 검증한다.

현재 `005930`은 식별 대조에 성공했고 다른 여섯 관측이 N이었다. 후속 버전에서 이 사례의 투자주의환기만 비적용으로 분리하면 제한 점검의 검토 사유가 해소될 수 있다. 이는 기대하는 회귀 검증 결과이지 이번에 계산한 새 결과나 현재 투자 후보 승인이다. API와 마스터의 관측 시각 차이, 신선도, 보통주 유형·상장 상태, 시장경보와 주문 Risk 검사는 여전히 별도다.

## 구현 완료 조건

후속 구현은 기존 `com.stock.strategy.universe.eligibility.restriction.kis.basicinfo.screening`과 그 아래 `result`의 책임 안에서 최소화한다. 규정 조회 Client·스케줄러·DB 테이블이나 일반적인 법규 엔진을 선행 생성하지 않는다.

- V1의 보존 결과·사유·버전을 유지하고 변경된 판정은 별도 버전으로 구분한다. 옛 JSON에 새 값을 채우지 않는다.
- 비적용 근거와 규칙 버전을 결과에서 추적할 수 있게 하되 원문 null·관측 미제공·다른 사유는 삭제하지 않는다.
- 적용 여부의 설명과 실제 차단 사유를 구분한다. 현재 상태 계산은 `reasons.isEmpty()`를 사용하므로, 비차단 설명 사유를 추가하는 것만으로는 검토 필요가 해소되지 않는다. 상태 계산과 결과 생성자 정합성을 함께 설계한다.
- 비적용 근거를 확인할 수 없으면 현행 보수적 처리를 유지한다. N 기본값이나 종목명 추정으로 우회하지 않는다.
- 운영 후보·주문과 과거 백테스트에 바로 연결하지 않는다. `AS_OF_VERIFIED`, `informationAvailableAt`과 최종 거래 허가를 생성하지 않는다.

구현 검증에서는 KOSPI 미제공과 나머지 여섯 N, KOSDAQ Y·N·공백, 다른 제한 Y·미확인, 식별 대조 실패, 미확정 시장·규격을 비교한다. 비적용 설명이 제외 신호를 가리거나 결과 생성자·JSON 복원에서 차단 사유를 제거할 수 없는지도 확인한다. 기존 보존 응답 10건은 새 버전 결과를 별도 보고서로 만들고 V1 보고서를 덮어쓰지 않는 방식으로 비교한다.

## 보존 증적과 변경 범위

증적은 Git 제외 경로 `build/kis-investment-caution-applicability-validation-01/`에 둔다. `capture-sources.ps1`은 고정한 네 규정의 공개 조회만 수행하고, 새 실행 폴더와 파일을 `CREATE_NEW`로 보존한다. 현재 `run-02/source-capture.json`에 요청 방식·bookid·수신 시각·상태·길이·SHA-256과 KIS 헤더 보존 검사를 기록했다.

규정 열람은 포털의 익명 세션과 공개 조회 POST를 사용한다. `bookid`를 붙인 GET으로 직접 열면 오류 페이지가 반환되어, 문서의 공식 진입 링크에서는 포털의 해당 규정 항목을 선택해야 한다. 보존 원문 링크는 로컬 증적을 가진 환경에서만 열린다. 익명 세션 값은 KIS 액세스 토큰이나 계좌 인증정보가 아니다.
