# KIS 주식기본조회 실전 응답 검증

## 판정과 범위

2026-10-06 실전 서버의 주식기본조회로 미리 고정한 10개 사례를 조회했다. **10건 모두 HTTP 200, `rt_cd=0`, `msg_cd=KIOK0530`을 반환했다. 표준코드·시장·증권 그룹·해당 시장 상장일·거래정지·관리종목은 기존 마스터 원문과 모두 일치했다.**

단, 응답 `pdno`는 요청 종목번호와 다른 12자리 `00000A…` 형태다. 주식종류 코드는 8건에서 공식 정의와 연결됐지만 ETF와 정리매매 사례 2건은 빈 문자열이었다. SPAC 사례는 주권 그룹과 보통주 코드를 반환했다. 따라서 일부 필드의 성공으로 전체 조합, 종목 자격이나 과거 모집단 검증을 승인하지 않는다.

기존 모의투자 설정과 분리한 일회성 조회다. 토큰 1회·주식기본조회 10회만 실전 서버에 요청했고 계좌·주문·취소·모의 서버·KRX 요청과 자동 재시도는 모두 0회다. `DESIGN_ONLY`, `runtimeSelectionImplemented=false`, `eligibilityOrHistoricalPopulationVerified=false`를 유지한다.

## 사전 계획과 호출 통제

[KIS 종목 자격 대체 원천 검증](kis-stock-eligibility-source-validation-01.md)의 10개 사례와 원래 선택 기준을 그대로 사용했다. 이전 관측의 모의 미지원·호출 0회 기록은 변경하지 않았다. 원천 정의는 [KIS 주식기본조회 공식 문서](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/quotations/search-stock-info)와 이전에 보존한 공식 상세 규격 SHA-256 `1fbf349c755a3f54469450e0b7ca89ee3aa3a779e4a33286348cc2e198c0567a`를 사용했다. 이번에 공식 문서나 마스터를 다시 다운로드하지 않았다.

실전 조회용 키는 로컬 `.env`의 `KIS_READONLY_APP_KEY`, `KIS_READONLY_APP_SECRET`에서 읽었다. 이 이름은 검증 도구의 용도 표시이며 증권사가 읽기 전용 권한을 부여했다는 뜻은 아니다. 기존 모의 키를 대체하거나 공통 `broker.kis` 설정을 바꾸지 않았다.

| 통제 항목 | 적용 범위 |
| --- | --- |
| 서버 | HTTPS `openapi.koreainvestment.com:9443`만 허용 |
| 인증 요청 | `POST /oauth2/tokenP` 최대 1회 |
| 종목 요청 | `GET /uapi/domestic-stock/v1/quotations/search-stock-info` 최대 10회 |
| 종목 요청 인자 | `PRDT_TYPE_CD=300`, 사전 고정한 `PDNO`만 사용 |
| TR ID | `CTPF1002R` |
| 호출 간격 | 각 종목 요청 전에 1,100 ms 대기 |
| 재시도·연속 조회·redirect | 모두 금지. 실패 시 남은 사례는 미조회로 기록 |
| 응답 제한 | 1 MiB, 연결 15초·읽기 5초 제한, 읽기 루프 경과 제한 |
| 비밀정보 | 키·secret·토큰·인증 헤더·인증 응답 본문을 저장하지 않음. 종목 응답에 비밀값이 반사되면 저장하지 않음 |
| 재실행 | 호출 전 `CreateNew` 시도 기록. 같은 관측에서 불확실한 호출을 반복하지 않음 |

사전 오프라인 검사에서 허용 요청 2개와 차단 요청 8개를 확인했다. 차단 사례는 주문, 잔고, 취소, 모의 서버, 계좌 인자 추가, 다른 서버, 종목정보 POST, 토큰 URL의 추가 인자다. 실제 HTTP 함수에서도 같은 경로 검사를 수행하며 계좌·주문 서비스나 Spring ApplicationContext를 시작하지 않았다.

## 실제 응답

아래 코드는 원문 값이다. `빈 문자열`은 필드가 존재하지만 값이 `""`였다는 뜻이며 누락·`000`·정상 여부로 치환하지 않는다.

| 요청 종목 | 원문 이름 | 시장 코드 | 그룹 | 주식종류 | 거래정지 | 관리종목 |
| --- | --- | --- | --- | --- | --- | --- |
| `005930` | 삼성전자 | `STK` | `ST` | `101` | `N` | `N` |
| `000250` | 삼천당제약 | `KSQ` | `ST` | `101` | `N` | `N` |
| `005935` | 삼성전자우 | `STK` | `ST` | `201` | `N` | `N` |
| `000087` | 하이트진로2우B | `STK` | `ST` | `202` | `N` | `N` |
| `069500` | KODEX 200 | `STK` | `EF` | 빈 문자열 | `N` | `N` |
| `0004Y0` | 디비금융제14호스팩 | `KSQ` | `ST` | `101` | `N` | `N` |
| `000040` | KR모터스 | `STK` | `ST` | `101` | `N` | `Y` |
| `007330` | 푸른저축은행 | `KSQ` | `ST` | `101` | `N` | `N` |
| `000300` | DH오토넥스 | `STK` | `ST` | `101` | `Y` | `N` |
| `067770` | 세진티에스 | `KSQ` | `ST` | 빈 문자열 | `Y` | `Y` |

`101`은 6건, `201`·`202`는 각각 1건, 빈 문자열은 2건이다. 이 건수는 독립적인 주식종류 필드 관측이며 운영 분류 결과가 아니다. `201`~`220`의 나머지 코드, 다른 그룹·시장, 미정의 값과 모든 허용 조합을 실측한 것은 아니다.

### 상품번호와 종목 식별

`005930` 요청의 응답 `pdno`는 `00000A005930`, `0004Y0` 요청은 `00000A0004Y0`다. 10건 모두 `00000A`와 요청 코드가 이어진 12자리 형태를 관측했다. 요청 코드와 원문 `pdno`의 직접 동등 비교는 10건 모두 `DIFFERENT_OBSERVATION`으로 보존했다.

이는 곧바로 다른 종목을 받았다는 뜻도, 모든 상품번호에서 접두부를 지워도 된다는 뜻도 아니다. **임의의 마지막 6자리 추출이나 공백·접두부 정규화 정책을 추가하지 않았다.** 별도의 공식 상품번호 변환 계약 확인이 필요하다.

`std_pdno`는 10건 모두 마스터의 12자리 표준코드와 정확히 일치했다. 예를 들어 `005930`은 `KR7005930003`, 영숫자 코드 `0004Y0`는 `KR70004Y0000`다. 시장과 증권 그룹도 일치했지만, 이는 이번 응답과 보존 마스터의 대조 결과이지 향후 모든 응답의 식별 연결 승인이나 표준코드 변경 이력 검증은 아니다.

### 제한 정보와 빈 값

SPAC 원문 `Y` 사례 `0004Y0`는 `ST/101`을 반환했다. 보통주 코드만으로 SPAC을 일반 투자 후보로 승인하지 않는다. `007330`은 마스터에서 투자주의환기 `Y`지만 주식기본조회에는 해당 원문 필드가 없었다. 이번 10건의 응답에는 마스터의 SPAC·투자주의환기·정리매매 전용 필드가 없으므로, 이 API만으로 해당 제한을 대체했다고 판단하지 않는다.

ETF `069500`은 그룹 `EF`를 반환했지만 주식종류는 빈 값이었다. 정리매매 원문 `Y`인 `067770`도 그룹 `ST`, 거래정지·관리종목 `Y`와 함께 주식종류 빈 값을 반환했다. 빈 종류를 `101`이나 `000`으로 보충하지 않고, 이름·과거 KRX 유형 결과로 현재 API의 빈 값을 덮어쓰지 않는다.

응답의 `lstg_abol_dt`, `scts_mket_lstg_abol_dt`, `kosdaq_mket_lstg_abol_dt`는 10건 모두 빈 문자열이었다. 이 표현만으로 현재 상장 상태나 과거 상장폐지 여부를 확정하지 않는다.

`nxt_tr_stop_yn`은 10건 모두 `N`이었다. `cptt_trad_tr_psbl_yn`은 삼성전자·삼천당제약만 `Y`, 나머지는 `N`이었다. 특히 KRX 거래정지 `Y`인 `000300`, `067770`도 NXT 정지 필드는 `N`이었다. 공식 정의상 NXT 정지의 `N`은 비대상도 포함하므로 KRX 정지 해제·주문 가능 여부로 사용하지 않는다.

마스터 수집 시각은 `2026-10-05T09:32:35.795200200Z`~`09:32:36.202168500Z`, 이번 실측은 `2026-10-06T06:27:04.8115818Z`~`06:27:16.7564289Z`다. 같은 값의 반복 관측으로 같은 적용 시점이나 과거 정보 가용성을 만들지 않는다. 불일치가 있었다면 서로 다른 시점의 상태 변경 가능성을 보존해야 한다.

종목 요청의 HTTP 송수신 구간은 최소 39 ms·최대 57 ms·평균 50.7 ms, 합계 507 ms였다. 토큰 요청은 211 ms, 요청 전 대기와 로컬 처리를 포함한 전체 구간은 약 11.945초였다. 이 작은 실측을 전시장 일괄 조회의 성능·Rate Limit·운영 SLA 보장으로 확장하지 않는다. 운영 Run에서 전종목을 개별 호출하는 기능도 추가하지 않았다.

## 보존과 재현

원문과 임시 도구는 Git 제외 경로 `build/kis-stock-eligibility-source-validation-02/`에 보존한다. 운영 Java 패키지에 새 클래스를 추가하지 않았다.

| 증적 | SHA-256 |
| --- | --- |
| 호출·검증 도구 `observe.ps1` | `647d0093e91beb4d563c6144d53c283e346f185097201e690590195b5eadecf6` |
| 호출 결과 `collection.json` | `5717306eb2efb8a34c509b746a7480b660437a2cd2889192007906dfda91a390` |
| 최초 검증 `verification.json` | `19950372bf58c5376b6c7874099fa683d85f40fc4dbaee200d3148a33800eae5` |
| 재현 검증 `replay-verification.json` | `7788a5ee018acd5d053c7daf6da44507da993bd6bcdae5d70172214cf986abe6` |

`preflight.json`은 고정 사례, 경로 통제 검사, 기존 증적과 실행 전 설정의 해시를 보존한다. `collection-attempt.json`은 HTTP 요청 전에 도구와 계획의 해시를 고정한다. 각 종목의 `*-attempt.json`, `*-response.bin`, `*-metadata.json`은 요청 시각·원문 바이트·크기·해시·시간·응답 코드를 연결한다. `token-metadata.json`에는 발급 성공·HTTP 상태·시간만 저장하고 인증 응답 본문은 저장하지 않았다.

네트워크 없는 검증을 두 번 실행했다. 표준 JSON 값으로 읽은 두 보고서는 `verifiedAt`을 제외한 전체 구조가 같았다. 원문 10건, 호출 범위, 고정 사례, 이전 관측과 마스터·규격·운영 설정·`.env` 무변경을 확인했다. 최초 호출 때의 도구 해시도 현재 보존 도구와 일치했다. 비밀정보 검사와 문서 링크 검사는 별도로 수행했다.

```powershell
.\build\kis-stock-eligibility-source-validation-02\observe.ps1 -Mode Replay -ReportName verification-recheck.json
```

`ReportName`은 아직 없는 `.json` 파일명이어야 한다. 기존 보고서와 HTTP 시도 기록은 `CreateNew`로 덮어쓰기를 거절하며 재현은 Broker를 호출하지 않는다. 증적을 보존하려면 `gradlew clean`을 실행하지 않는다.

## 운영 연결 경계

이번 결과는 KIS에서 현재 종목 유형과 일부 제한 정보를 보완할 수 있는 실측 근거다. 상품번호 변환, 빈 값·상충 조합, 마스터 제한 필드 추출·신선도와 자격 제외 정책은 별도로 구현·검증해야 한다. API 유형 코드로 MST의 ETP 공백 정의를 소급 확정하지 않는다.

`StockEligibilityInput`, `StockEligibilityPolicy`, 기존 KIS·KRX 유형/제한 정책과 운영 후보 목록은 변경하지 않았다. `AS_OF_VERIFIED`, `informationAvailableAt`, 상장 상태나 주문 허가를 생성하지 않는다. KRX를 삭제하거나 KIS만으로 과거 모집단 검증이 끝났다고 선언하지 않는다.

운영 Java·설정·DB·스키마·Harness·Risk·AI Prompt·스케줄·Docker·`.env` 변경은 없다. 서버를 시작·정지·재배포하지 않았고 OpenAI 호출·실제 주문·커밋·Push는 수행하지 않았다. 운영 코드 변경이 없어 Gradle 테스트를 재실행하지 않고 경로 통제 검사와 원문 오프라인 재현으로 검증했다.
