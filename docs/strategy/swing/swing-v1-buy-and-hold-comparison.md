# SWING_V1 동일 종목 매수 후 보유 비교

## 목적과 범위

SWING_V1의 진입과 청산이 같은 종목을 단순 보유하는 것과 어떤 차이를 만드는지 확인한다. 기존 KOSPI 벤치마크는 시장 참고값으로 유지하고, 같은 종목의 매수 후 보유를 별도의 백테스트 비교 대상으로 추가한다.

이 비교는 운영 전략이나 Broker 주문 경로가 아니다. SWING 정책, 운영 Risk Guard, 전략별 자금 배분과 스케줄러 설정을 변경하지 않는다. 비교 대상이 높은 수익을 보였다는 이유로 실제 주문 한도를 완화하지 않는다.

## 고정된 비교 계약

- 각 SWING 보고서와 종목, 초기 현금, 전체 평가일, 평가 시각 메타데이터와 비용 모델이 같아야 한다.
- 첫 평가일의 저장된 시가에 한 번만 매수한다. 이후 추가 매매, 리밸런싱과 가격 하락 후 재진입은 하지 않는다.
- 매수 예산은 `floor(initialCashAmountKrw * initialAllocationRatio)`다.
- 슬리피지와 반올림된 수수료를 포함한 매수 정산금액이 예산 이하여야 한다. 이 조건을 만족하는 최대 정수 수량을 선택한다.
- 최초 예산으로 1주도 살 수 없으면 해당 구간 전체를 현금으로 유지한다. 이후 주가가 내려가도 매수하지 않는다.
- 남은 현금에는 이자수익을 추가하지 않는다. 배당과 기업행위는 현재 SWING 백테스트와 마찬가지로 별도 반영하지 않는다.
- 매 평가일 자산은 `남은 현금 + 고정 보유 수량 * 당일 시가`로 평가한다. 장중 저가 기준 손실이나 실제 09:10 체결을 재현하는 모델은 아니다.

각 종목에 다음 두 배분을 결과 확인 전에 고정한다. 결과가 잘 나오는 비율을 사후에 탐색하지 않는다.

| 최초 배분 | 비교 목적 | 해석 제한 |
| --- | --- | --- |
| 100% | 같은 종목을 계속 보유했을 때의 기회비용 | 운영 주문 한도를 따르는 전략이 아니며 손실 위험이 더 클 수 있다. |
| 10% | 현재 예시 1회 주문 상한과 같은 초기 예산의 보조 비교 | 운영 설정을 자동으로 읽는 값이 아니다. 보유 중 평가 비중이 바뀌므로 SWING과 동일한 위험 조건이 아니다. |

두 비교 모두 전체 초기 현금을 수익률 분모로 사용한다. 10% 비교에서 투자한 금액만 분모로 바꾸지 않는다. 종목별 초기 현금은 서로 독립적이며 여러 종목을 하나의 공유 계좌로 운용한 결과가 아니다.

## 비용과 성과

`TradeCostCalculator`를 사용해 SWING과 같은 매수·매도 수수료, 매도 세금, 불리한 방향의 슬리피지와 원 단위 올림·내림을 적용한다. 매수 비용은 최초 현금 차감에 이미 포함된다.

최종 결과는 다음 두 값을 구분한다.

1. 평가금액 기준: 마지막 평가일 시가로 보유 주식의 가치를 계산한다. 아직 지불하지 않은 최종 매도 비용은 포함하지 않는다.
2. 청산비용 보정 기준: 마지막 평가일 시가를 기준으로 전량 매도했을 때의 슬리피지·수수료·세금을 한 번 차감한다. 이는 청산 가정이지 실제 매도나 포트폴리오 상태 변경이 아니다.

청산비용 보정 후 자산은 `남은 현금 + 최종 매도 정산금액`과 같아야 한다. 매수 비용을 다시 빼거나 매도 비용을 두 번 빼지 않는다. SWING은 기존 `terminalLiquidationEstimate`의 보정 수익률과 비교한다.

MDD는 기존 `BacktestPerformanceCalculator`로 계산한다. 최초 매수 직전 현금을 시작 고점으로 포함하며, 매수 비용 반영 후 매일의 시가 평가곡선을 사용한다. 마지막 가정 매도 비용은 일별 평가곡선과 MDD에 추가하지 않는다. 보고서에서 청산비용 보정 수익률과 시가 평가곡선 MDD를 혼동하지 않는다.

SWING 보고서와 보유 비교 결과 모두 같은 평가곡선 계산 규칙의 `exposureSummary`를 포함한다. 보유 평가일 비율, 현금 유지일을 포함한 평균 투자 비중과 최대 관측 비중을 수익률·MDD와 함께 확인한다. 최초 배분 10%를 평균 투자 비중 10%로 그대로 기록하지 않으며, 비용과 정수 수량이 반영된 실제 곡선을 사용한다. 총자산 0 또는 유효하지 않은 평가일 목록은 노출 계산을 거절한다. 세부 계산 계약은 [전략 계약](swing-v1-strategy-contract.md)의 Benchmark And Validation을 따른다.

## 코드와 데이터 검증

- 요청과 결과: `com.stock.backtest.comparison.buyandhold.model`의 `BuyAndHoldBacktestRequest`, `BuyAndHoldBacktestResult`.
- 계산: `com.stock.backtest.comparison.buyandhold.calculation.BuyAndHoldBacktestCalculator`.
- 통합: `SwingV1BacktestExperimentEvaluationService`가 SWING 실험을 실행한 뒤 종목당 저장소 조회 한 번을 두 배분에서 재사용한다.
- 반환: `SwingV1BacktestExperimentEvaluation.buyAndHoldResults`에 종목별 두 결과와 전체 평가곡선을 담는다. 기존 SWING 실행 결과와 요약은 유지한다.

평가일 누락, 추가 또는 다른 종목의 데이터는 거부한다. 저장소를 다시 읽었을 때의 시가는 SWING 각 Step의 `BACKTEST_DAILY_OPEN` 판단 근거와도 비교한다. 가격, 종목, 관측 시각이나 데이터 출처가 다르면 부분 결과를 성공으로 반환하지 않는다. 이 검증은 비교 입력의 일치를 확인할 뿐 원본 데이터의 정확성이나 실제 거래일의 완전성을 보장하지 않는다.

최초 매수 수량 계산에는 첫날 가격과 사전에 정한 현금·배분·비용만 사용한다. 같은 날 종가, 미래 가격과 미래 수익률로 매수 시점을 선택하지 않는다.

## 실행과 검증

기존 [수동 백테스트 실행 절차](swing-v1-manual-backtest.md)를 사용한다. 별도의 배분 설정이나 외부 API 호출은 필요하지 않다. `manual backtest buy-and-hold comparison` 로그에는 배분, 예산, 수량, 잔여 현금, 평가금액 수익률, 최종 청산 비용, 보정 수익률, MDD와 SWING 대비 차이가 기록된다. 로그의 수익률은 소수 비율이며 `0.1`은 10%다.

같은 로그의 `swingExposureSummary`와 `buyAndHoldExposureSummary`에는 각 결과의 노출 요약이 함께 기록된다. 실제 장중 보유 시간이나 동일 위험 조건을 뜻하지 않는다.

```powershell
.\gradlew.bat test --tests "com.stock.backtest.comparison.buyandhold.*" --tests "com.stock.backtest.strategy.swing.v1.experiment.*" --console=plain
```

검증 대상은 비용을 포함한 최대 매수 수량, 현금 유지, 단일 평가일, 상승·하락·횡보, MDD, 청산비용 중복 차감, 미래 가격 변경, 평가일·시각·시가 불일치, 여러 종목의 독립 자금과 결과 로그다.

보존한 확대 백테스트 스냅샷을 사용한 실제 비교는 [비교 관측 결과 03](validation/swing-v1-buy-and-hold-observation-03.md)에 기록한다. 비교 기능 추가 이후 평가 결과에는 새 필드가 포함되므로 과거 전체 JSON의 해시와는 달라진다. 과거 관측 결과의 해시를 덮어쓰거나 전략 변경으로 해석하지 않는다.

## 해석 제한

매수 후 보유 대비 초과수익은 위험 조정 알파나 양의 기대수익의 입증이 아니다. 최초 배분과 보유 중 비중, 매수 시점과 기간이 다르다. 비용 모델 검증, 수정주가·기업행위·배당 처리, 다종목과 미사용 구간 검증은 여전히 필요하다. 이 작업은 이미 관측한 구간의 설명이며 실제투자 승격 조건을 대신하지 않는다.
