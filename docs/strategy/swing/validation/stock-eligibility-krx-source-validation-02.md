# KRX 종목기본정보 실측 사전점검

후속 [실응답 관측 및 KIS 식별 대조](stock-eligibility-krx-source-validation-03.md)에서는 사용자 확인을 거쳐 `2026-10-02` 기준의 두 시장 응답을 수집하고 기존 KIS 자료와 식별자를 대조했다. 아래 기록은 2026-10-05 당시의 사전점검 결과이며 변경하지 않는다.

## 현재 판정

2026-10-05 KRX 종목기본정보의 최소 실측을 준비하고 로컬 사전점검을 실행했다. **인증키 설정과 API 승인·이용 범위·요청 기준일이 확인되지 않아 실제 데이터 요청은 보내지 않았다.** 이번 결과는 실응답 수집이나 KIS 식별 대조 완료가 아니라 `NOT_READY_NO_REQUEST_SENT` 상태의 기록이다.

[앞선 공개 명세 검증](stock-eligibility-krx-source-validation-01.md)에서 확인한 가설은 KRX의 표준 코드·단축 코드·증권구분·주식종류가 KIS 유형 보류를 보완할 근거가 될 수 있다는 것이다. 실제 값과 연결 사례를 얻지 못했으므로 이 가설은 아직 검증되지 않았다. 기존 KIS 분류 정책, 원문과 보류 사유는 그대로 유지했다.

## 사전점검 결과

| 확인 항목 | 결과 | 판정 범위 |
| --- | --- | --- |
| 실행 프로세스 `KRX_AUTH_KEY` | 설정 없음 | 키 발급 여부나 다른 실행 환경의 설정 여부를 뜻하지 않는다. |
| 실행 프로세스 `KRX_API_KEY` | 설정 없음 | 대체 이름의 설정 여부만 확인했다. |
| 로컬 `.env`의 `KRX_` 설정 이름 | 0개 | KRX 설정의 이름만 조사했다. 기존 다른 자격증명은 출력하거나 변경하지 않았다. |
| 두 시장 종목기본정보 API 활용 승인 | 미확인 | 사용자 확인을 받지 못했다. 승인 거절이나 미신청으로 단정하지 않는다. |
| 연구용 수집·원본 및 결과 보존의 이용 범위 | 미확인 | 약관 수락이나 이용 가능성에 대한 판단을 대신하지 않는다. |
| 요청 기준일 | 미확정 | 현재 날짜나 KIS 수집 날짜를 임의로 지정하지 않았다. |
| 보존된 KIS 파일 7개 | 기존 크기·SHA-256과 일치 | 최초 관측 결과의 고정 해시를 확인한 뒤 각 파일을 대조했다. |
| 보존된 KRX 공개 자료 7개 | 기존 크기·SHA-256과 일치 | 앞선 공개 자료 수집 보고서의 고정 해시를 확인한 뒤 각 파일을 대조했다. |

KRX의 [공식 이용방법](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO003.jsp)은 인증키 신청과 원하는 API의 활용 신청에 승인 절차를 안내한다. KIS 인증키를 대신 사용하거나 페이지의 공개 샘플 키를 사용하는 방식으로 진행하지 않았다. 인증키 존재 확인도 실제 인증 성공이나 API 승인 증명과는 구분한다.

프로세스 환경 변수 목록을 열거하는 첫 시도에서는 PowerShell 환경 변수 공급자의 중복 키 오류가 발생했다. 이후 `KRX_AUTH_KEY`와 `KRX_API_KEY`를 개별 조회하여 설정 여부만 확인했다. 이 오류는 KRX 서버 응답이 아니며 외부 요청을 발생시키지 않았다.

## 로컬 헬퍼와 증적

사전점검 헬퍼는 Git 제외 경로 `build/stock-eligibility-krx-source-validation-02/verify-preflight.ps1`에 만들었다. 이 헬퍼는 외부 API 호출 기능이 없으며 다음 항목만 검사하고 `preflight.json`을 새 파일로 생성한다.

1. 고정한 KIS·KRX 관측 보고서의 SHA-256과 예상 파일 수를 검증한다.
2. 보존된 원본 14개의 크기와 SHA-256을 각 관측 보고서와 대조한다.
3. 프로세스의 KRX 키 설정 여부와 `.env`의 KRX 설정 이름만 확인한다. 키 값은 보고서에 직렬화하지 않는다.
4. 두 시장 승인·이용 범위에 대한 명시적인 사용자 확인과 별도로 지정한 기준일의 형식을 검사한다.
5. 확인되지 않은 조건을 기록하고 데이터 요청 없이 종료한다.

승인과 이용 범위의 확인 플래그는 기본적으로 꺼져 있다. 플래그가 켜져도 사용자 선언일 뿐 제공자 승인을 자동으로 검증하지 않는다. 날짜 형식 검사는 거래일 여부·자료 제공 여부·정보 가용 시각을 승인하지 않는다. 모든 사전조건을 선언하더라도 이 헬퍼 자체는 데이터를 요청하지 않는다.

이번에는 기준일이나 확인 플래그 없이 실행했다. 점검 시각은 `2026-10-05T13:02:15.2692736+00:00`이며 다음 네 조건이 미확인으로 남았다.

- `KRX_AUTH_KEY_NOT_CONFIGURED_IN_PROCESS`
- `BOTH_MARKET_API_APPROVALS_UNCONFIRMED`
- `COLLECTION_AND_RETENTION_USAGE_SCOPE_UNCONFIRMED`
- `REQUEST_BASE_DATE_NOT_CONFIRMED`

`preflight.json`의 SHA-256은 `b3917f005e7c08b44be8c89779958e23ac7c53e2a9e4edb7df44f699c554fd46`이다. 기존 보고서가 있으면 헬퍼가 덮어쓰기를 거절하는 것을 재실행으로 확인했고 보고서 해시도 유지됐다. 기존 증적을 지우거나 재사용하지 않고 후속 점검은 별도 관측 경로에 남긴다.

## 실측 재개 조건

실측 전에 KRX 인증키의 안전한 설정 경로, 두 시장 종목기본정보 API 활용 승인, 수집과 로컬 보존의 이용 범위, 요청 기준일과 호출 예산을 확인해야 한다. 인증키는 대화·Git·로그에 남기지 않는다. `.env` 자동 로딩이나 Docker 환경 변수 변경은 이번에 추가하지 않았다.

재개할 실측은 앞선 문서의 범위를 유지한다. 비교 가능한 기준일 하나에 KOSPI와 KOSDAQ을 각각 최대 한 번씩, 총 2회 요청하고 원본 응답 바이트·상태·수집 시각·해시를 보존한다. 해당 키의 다른 사용량과 별도 한도도 사전에 확인한다. 응답이 실패·분할·잘림·누락 상태여도 자동 재시도·페이지 추가·기간 확대를 하지 않는다. 두 요청으로 전체 시장이 완성된다는 보장은 하지 않는다.

응답 확보 후에는 표준 코드의 정확한 일치와 단축 코드 교차 대조를 사용하고 미연결·중복·모호한 행을 함께 남긴다. 주식종류 값의 관측은 공식 의미 검증과 구분하며, 요청 기준일이나 수집 완료 시각을 과거 `informationAvailableAt`으로 채우지 않는다. 현재 KIS 자료와의 연결만으로 과거 자격을 승인하지 않는다.

## 변경하지 않은 영역

새 Java 클래스·Provider·DB 저장·스키마·후보 선정·백테스트·주문 연결을 추가하지 않았다. `DESIGN_ONLY`, `runtimeSelectionImplemented=false`, `eligibilityOrHistoricalPopulationVerified=false`를 유지한다. 기존 KIS 원본·설정·분류 정책과 Docker·계좌·주문·OpenAI는 변경하거나 호출하지 않았다. 커밋과 Push도 실행하지 않았다.

사전점검 보고서의 상태·미확인 조건·요청 수·미측정 필드와 덮어쓰기 방지를 로컬에서 확인했다. 애플리케이션 코드 변경이 없어 Gradle 테스트는 재실행하지 않았다. 실제 응답 수집과 코드 대조는 사전조건 확인 전까지 미완료다.
