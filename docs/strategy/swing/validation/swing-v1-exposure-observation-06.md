# SWING_V1 저장 평가곡선 노출 관측 결과 06

## 목적과 판정

2026-10-01 [기간별 관측 결과 05](swing-v1-period-observation-05.md)의 두 원본 결과에 저장된 평가곡선으로 자금 노출을 계산했다. 기존 수익률·MDD·체결·포트폴리오·완료 거래를 재계산하거나 전략을 다시 실행하지 않았다. DB·KIS·OpenAI에는 연결하지 않았다.

새 공통 계산기의 결과는 별도의 정확한 분수 연산 검산과 일치했다. A의 SWING 평균 투자 비중은 1.61722~4.52706%, B는 0.89031~12.43314%다. C의 세 종목은 보유 없이 현금을 유지했고 NAVER의 평균 투자 비중은 0.37993%였다.

**계산 정합성과 저장 곡선에서의 노출 차이는 확인했다. 낮은 MDD의 원인을 확정하거나 위험 조정 알파·양의 기대수익을 입증한 관측은 아니다.** 투자 비중으로 수익률을 나누거나, 이 결과를 근거로 주문 한도를 확대하지 않았다.

## 고정된 계산 기준

- 원본은 관측 05의 A·B·C 기간, 후보 순서 `005930`, `000660`, `005380`, `035420`, 독립 실행 `01`·`02`다.
- SWING은 `runResult.steps`의 null이 아닌 `equitySnapshot`, 보유 비교는 `equityCurve`를 사용한다. 새 평가일이나 초기 현금 스냅샷을 덧붙이지 않는다.
- 전체 평가일 수는 A 241개, B 243개, C 125개이며 시가 주문 반영 후 평가 시점 기준이다. 실제 장중 보유 시간이나 달력 일수 기준이 아니다.
- 보유는 주식 평가금액이 양수인 평가일로 센다. 평균은 모든 평가일의 `주식 평가금액 / 총자산`을 동일 가중치로 평균하며 현금 유지일을 포함한다.
- 최대 투자 비중은 위 비중의 관측 최댓값이다. Risk 설정의 `max-position-ratio`와 별개의 지표다.
- 비율은 `BigDecimal`, `DECIMAL128`이며 표에만 100을 곱하고 소수점 다섯 자리로 반올림한다.
- null·빈 곡선·null 원소, 중복·역순 평가일과 총자산 0은 거절한다. 총자산 0을 현금만 보유한 노출 0으로 숨기지 않는다.

최초 100%·10% 보유 비교는 원본과 동일하며 새 배분을 탐색하지 않았다. 평균 투자 비중은 초기 배분과 같지 않을 수 있다.

## 독립 검산과 보존

기간별 두 원본 실행에서 SWING 24개, 매수 후 보유 48개로 총 72개 곡선을 계산했다. 같은 기간·종목·비교 배분의 두 실행은 노출 요약 다섯 값 모두 같았다. 반복 실행을 새로운 독립 거래 표본으로 집계하지 않는다.

검산은 Java 계산기의 일별 소수 나눗셈을 재사용하지 않고 `BigInteger` 분수의 정확한 합·비교로 보유 건수·평균·최대 비중을 계산했다. 정확한 분수 결과를 50자리 정밀도 소수로 변환하고 구현 결과와 절대 오차 `1e-30` 이내인지 비교했다. `DECIMAL128`의 반올림 때문에 무한소수의 완전한 비트 일치를 요구한 것은 아니다.

72개 곡선의 전체·보유 건수, 입력 보존과 세 비율 및 여섯 원본 파일의 실행 전후 해시를 확인한 **438개 항목에서 불일치 0개**였다. 관측 05의 여섯 원본 결과 해시는 그대로 유지됐다. 전략 실행·외부 수집·DB 조회·주문과 원본 파일 수정은 없었다.

추적하지 않는 `build/exposure-observation/`에 `VerifyExposureObservation.java`와 `run-01.json`을 남겼다. 출력에는 여섯 원본 경로·SHA-256, 각 기간·실행·종목·비교의 새 노출 요약과 검산 건수가 있다. `build/`는 `clean`으로 삭제될 수 있으므로 원본 보관을 영구적으로 보장하지 않는다.

원본 JSON에 `exposureSummary`가 없다고 자동으로 0을 채우지 않는다. 기존 곡선에서 새 요약을 별도로 계산하며, 새 필드가 추가된 현재 보고서 전체 JSON의 해시를 과거 해시와 동일하다고 주장하지 않는다.

## 구현과 검증 범위

공통 계산과 불변 요약은 `com.stock.backtest.performance.exposure`에 있다. SWING 보고서와 보유 비교 결과 모두 `exposureSummary`를 포함하고 생성 시 원본 곡선과 다섯 값의 일치를 검증한다. 상태나 외부 의존성이 없는 계산은 정적 함수로 두며 Spring Bean이나 새로운 저장소를 추가하지 않았다.

테스트는 현금 유지·전 기간 보유·매수와 매도 후 혼합 곡선, 단일 평가일, 개별 비율 평균·평가일 균등 가중치, 무한소수·큰 자산, 입력 보존·잘못된 입력을 포함한다. 보고서와 보유 비교 연결, 잘못된 요약 거절, JSON 새 필드와 기존 손익·비용 근거 보존 및 수동 Runner 로그 전달도 검증한다.

`./gradlew.bat test --console=plain`으로 전체 **1,493개 테스트 통과**, 실패 0개·건너뜀 0개를 확인했다. 새 테스트는 27개이며 기존 1,466개도 유지됐다.
