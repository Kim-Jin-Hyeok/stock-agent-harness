**기간별 실행, 계산 정합성과 전체 결과 값의 재현성은 확인했다. 반복 가능한 양의 기대수익이나 실제투자 승격은 입증하지 못했다.** B의 양수 수익률에는 미청산 보유의 평가이익이 포함되며, C에서는 세 종목이 매수 없이 현금을 유지했다. 기존 [다종목 관측 결과 04](swing-v1-multi-symbol-observation-04.md)의 연속 운용 결과와 혼합하지 않는다.

## 재현성과 독립 검산

기간마다 평가 서비스를 두 개의 독립 JVM에서 실행했다. 입력에는 요청·전략 설정·원본 OHLCV·지수 관측을, 결과에는 전체 Step·판단 근거·체결·포트폴리오·성과·매수 후 보유 비교·진단을 담았다. 실행 시각과 소요 시간은 별도 메타데이터다.

| 기간 | 1차 시작 KST / 소요 시간 | 2차 시작 KST / 소요 시간 | 전체 JSON 값 | 원본 바이트 해시 |
| --- | --- | --- | --- | --- |
| A | 18:28:50.8353902 / 6,131ms | 18:31:17.969988 / 5,064ms | 동일 | 동일 |
| B | 18:30:38.507775 / 6,036ms | 18:31:44.7290206 / 5,279ms | 동일 | 다름 |
| C | 18:30:58.9319304 / 3,390ms | 18:32:17.0606599 / 2,968ms | 동일 | 다름 |

시작 시각은 모두 2026-10-01이며 소요 시간은 평가 서비스 호출만 측정한다. Spring 시작, 사전 점검과 JSON 저장 시간은 제외한다.

B·C 원본 결과의 바이트 해시는 다르다. JSON 객체 필드 출력 순서 차이를 확인했고 숫자는 `BigDecimal`로 파싱해 전체 값을 비교했다. 모든 기간의 재귀 비교 차이는 0개다. 객체 키만 정렬하고 배열 순서·숫자·`null`을 보존한 정규화 결과 해시는 두 실행이 같았다. 원본 파일을 정렬하거나 덮어쓰지 않았으며 바이트 단위 재현성까지 통과했다고 주장하지 않는다.

초기 검산 도구의 PowerShell 배열 처리와 파라미터 이름 충돌을 수정했다. 예비 출력과 로그도 보존했으며 최종 판정 근거는 `audit-final-A.json`, `audit-final-B.json`, `audit-final-C.json`, `reproducibility-exact.json`이다. 이 도구 수정은 원본 입력·결과나 전략 규칙을 바꾸지 않았다.

## 데이터 보존과 실행 안전성

앱과 MySQL 컨테이너가 모두 중지된 상태에서 MySQL만 임시 시작했다. 전용 프로세스는 Web·KIS·OpenAI·자동 백테스트·모든 수집 및 주문 Scheduler를 비활성화하고, Flyway 비활성화·DDL `validate`·Hikari 읽기 전용 연결로 실행했다. 외부 API 호출, Broker 주문, 결과 DB 저장과 스키마 변경은 하지 않았다.

모든 실행 전후와 최종 점검에서 아홉 테이블 전체 행을 PK 순서로 조회한 내용 해시 및 건수가 사전 점검과 같았다. 종목과 지수 입력도 관측 04의 원본 입력과 동일했다.

| `current_price_observation` | 80 |
| `daily_price_bar` | 2,916 |
| `flyway_schema_history` | 3 |

네 종목의 729개 저장 날짜는 같은 범위의 KOSPI 날짜와 일치했다. 비양수 OHLC, 잘못된 고가·저가와 음수 거래량도 없었다. 이는 저장 데이터의 내부 정합성 검사이며 종목·지수에 함께 빠진 날짜, 원본 시세 정확성, 수정주가·배당·분할 등 기업행위나 당시 실제 제공된 데이터 버전까지 독립 검증한 것은 아니다.

검증 종료 후 MySQL도 다시 중지했다. 운영 앱을 시작하거나 Docker 이미지·설정·`.env`, 운영 Universe·스케줄·Risk·전략을 변경하지 않았다.

## 증거 위치와 회귀 확인

이번 문서는 Git 추적 대상이다. 일회성 Java·PowerShell 도구와 원본 증거는 기존 관측과 마찬가지로 추적하지 않는 `build/backtest-observation-05/`에 남겼다. 운영 패키지에 신규 클래스나 계층을 추가하지 않았다.

| 경로, 위 디렉터리 기준 | 내용 |
| --- | --- |
| `plan.json` | 평가 전 고정한 세 요청·설정·코드 기준·설정 파일 해시 |
| `inspect-database.json`, `inspect-coverage.json` | 사전 DB 내용 및 기간·이력 점검 |
| `run-a-01/` ~ `run-c-02/` | 기간별 두 실행의 `input.json`, `result.json`, `metadata.json` |
| `run-*-database.json`, `run-*-after-database.json` | 각 실행 전후 DB 내용 및 건수 |
| `reproducibility-exact.json` | 전체 값 비교와 원본·정규화 결과 해시 |
| `audit-final-A.json`, `audit-final-B.json`, `audit-final-C.json` | 독립 검산 결과 |
| `postflight-database.json`, `postflight-coverage.json` | 최종 DB 보존 및 이력 재점검 |
| `SwingV1Observation05.java`, `run-observation-05.ps1`, `audit-observation-05.ps1` | 기존 평가 서비스 호출 및 독립 검산 도구 |
| `*.log` | 준비·실행·도구 점검 로그 |

`build/`는 `clean`으로 삭제될 수 있으므로 이 문서만으로 원본 파일 보관이 보장되지는 않는다. 기존 관측 01~04와 그 원본은 덮어쓰지 않았다.

재실행 시에는 [수동 실행 문서](../swing-v1-manual-backtest.md)의 기존 서비스와 안전 조건을 사용하고, 위 조건을 새 실행 전에 명시한다. 외부 호출을 끄고 읽기 전용 DB·마이그레이션 비활성화 여부를 먼저 확인한다. 원본과 로그는 새 경로 또는 새 Label로 저장해야 하며 기존 `run-*-01`, `run-*-02`를 덮어쓰지 않는다. 기간마다 전체 전략을 실행하고 시작 현금·보유를 초기화한 뒤, 평가일·완료 거래·미청산 보유·비교 결과를 함께 확인한다.

`./gradlew.bat test --rerun-tasks --console=plain`을 실행했다. 전체 **1,466개 테스트 통과**, 실패 0개·건너뜀 0개다. 애플리케이션과 테스트 코드는 수정하지 않았다.

## 해석 한계

이번 관측은 전체 기간의 양수 결과가 모든 독립 시작 기간에서 유지되지 않고, 일부 평가이익은 미청산 보유에 의존함을 보여준다. 양의 기대수익을 반복 검증했다는 판정은 내리지 않는다.

짧은 C와 다른 초기 보유 상태, 적은 완료 거래 수, 고정된 네 종목, 미검증 비용과 일봉 시가 체결 근사가 포함된다. 결과가 좋았던 기간만 남기거나 손실·무거래 종목을 제외하지 않았고 전략을 재조정하지 않았다. 모의투자·실제투자 성과와 주문 품질은 이번 과거 데이터 관측으로 확인되지 않는다.
