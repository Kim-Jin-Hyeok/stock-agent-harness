# KRX 종목기본정보 기반 개별주 유형 보완 원천 검증

## 판정과 범위

2026-10-05 KRX의 유가증권·코스닥 종목기본정보 공개 페이지와 공식 개발 명세서를 확인했다. **표준 코드·단축 코드·시장·증권구분·주식종류 항목은 존재하지만, 실제 유형 값의 허용 집합과 과거 정보 가용성은 확인하지 못했다.** KRX를 개별주 유형의 보완 원천 후보로 검토하되 자동 분류나 종목 자격 승인에 아직 연결하지 않는다.

[KIS 현재 유형 해석 정책](../../../market/stock/master/stock-master-type-classification.md)은 KOSPI `EF/2/0`만 ETF로 해석한다. 기존 관측의 `ST` 2,719행은 모두 ETP 공백이며 전체 4,403행 중 3,244행이 유형 보류다. 이번 조사는 이 보류를 기본 유형으로 채우는 작업이 아니라, 독립적인 공식 원천으로 유형을 확인할 수 있는지 검토하는 작업이다. 기존 건수는 앞선 KIS 관측 결과이며 이번에 KRX 자료와 대조한 건수가 아니다.

공개 안내·명세서만 읽고 보존했다. 회원가입·본인인증·약관 동의·인증키 신청·API 활용 신청·제공자 문의를 하지 않았고 사용자 인증키나 페이지의 공개 샘플 키도 사용하지 않았다. 실제·샘플 종목 데이터 요청과 KIS 재수집은 0회다. `StockEligibilityInput`·새 Java 클래스·DB 저장·운영 후보·백테스트·주문 연결을 추가하지 않았으며 `DESIGN_ONLY`, `runtimeSelectionImplemented=false`, `eligibilityOrHistoricalPopulationVerified=false`를 유지한다.

## 요청과 응답 계약

공식 다운로드 DOCX의 서버 endpoint는 유가증권 `https://data-dbg.krx.co.kr/svc/apis/sto/stk_isu_base_info`, 코스닥 `https://data-dbg.krx.co.kr/svc/apis/sto/ksq_isu_base_info`다. 실제 요청은 보내지 않았다. 공개 페이지의 `/svc/sample/apis/` 경로와 승인 API를 구분하며, 페이지에 제시된 샘플 GET 예제를 실제 승인 API의 모든 HTTP 동작·오류 계약으로 확대하지 않는다.

두 시장 모두 `InBlock_1`에 기준일자 `basDd` 하나를 받는다. 공개 스키마는 문자열 길이 8과 예제 `20200414`를 제공한다. 다운로드 명세서의 `OutBlock_1`은 배열 형태의 구조 예제를 제시하며 응답 필드 12개는 모두 문자열이다. 기준일을 지정할 수 있다는 사실만으로 해당 날짜의 공개 당시 원본을 돌려준다는 뜻은 아니다. ## 식별 연결과 보완 원칙

다음은 **후속 구현을 위한 프로젝트의 설계 선택**이다. KRX가 KIS 코드의 의미나 교차 원천 연결을 보증했다는 뜻은 아니다.

먼저 각각의 원천에서 코드 형식·중복·시장 범위를 확인한 뒤 표준 코드의 정확한 일치로 연결하고 단축 코드를 교차 대조한다. 이름으로 연결하거나 앞자리 0·영숫자 코드를 숫자로 바꾸지 않는다. 서로 다른 표준 코드가 같은 단축 코드를 가리키거나 시장 범위가 맞지 않으면 임의 병합하지 않고 해당 연결을 보류한다. 코드 문자열의 보정도 별도 공식 규칙 없이 추가하지 않는다.

KIS의 원문과 단일 행 유형 해석 결과는 그대로 유지한다. KRX의 유형 근거를 얻더라도 KIS ETP 공백을 `0`으로 바꾸거나 기존 원문·사유·규칙 버전을 덮어쓰지 않는다. 후속 보완 결과에는 어느 원천의 어떤 필드로 유형을 확인했는지, 원문·요청 기준일·해시·규격과 연결 근거를 별도로 남기는 방향이다.

KIS 유형 null과 근거가 확인된 KRX 유형의 조합은 자동으로 유형 충돌이 아니다. 다만 KRX 유형 자체의 의미와 식별 연결을 먼저 확인해야 한다. 두 원천이 같은 적용 범위에서 각각 확인한 유형이 다르면 임의 우선순위로 해결하지 않고 보류한다. 적용일이 불명확하거나 서로 다른 날짜의 자료라면 먼저 시점 차이를 검토하며, 현재 KIS 관측을 과거 KRX 상태의 반증으로 사용하지 않는다.

일치 행만 남겨 전체 모집단이 완성됐다고 하지 않는다. KRX에 없는 KIS 행, KIS에 없는 KRX 행, 중복·연결 불가·유형 미확인 행을 모두 기록한다. 두 서비스와 KIS 마스터의 상품 범위가 동일하다는 근거가 없으므로 4,403행 전부의 일치를 요구하거나 누락을 곧바로 `NOT_LISTED`로 바꾸지 않는다.

## 시점과 자격 판정의 한계

`basDd`, `LIST_DD`, 실제 수집 완료 시각과 정보 가용 시각은 서로 다르다. 요청 기준일을 현재 입력의 `asOfDate`에 복사하거나 다운로드 완료 시각을 과거 `informationAvailableAt`에 넣지 않는다. 현재 공개 스키마의 적용일 항목이 비어 있다는 사실이나 API 명세 버전으로 이 시점 근거를 채우지도 않는다.

과거 기준일 응답이 당시 값인지 현재 정정본인지, 이후 상장폐지된 종목까지 포함하는지, 시장 이전·유형 변경을 어떤 시점으로 반영하는지 확인해야 한다. 이번 공개 명세 검토와 공식 도메인 검색으로 이 근거를 확보하지 못했다. 검색 결과 부재를 자료가 존재하지 않는다는 증명으로 사용하지 않으며, 과거 모집단의 완전성과 당시 정보 가용성은 미확인으로 남긴다.

기존 `StockEligibilityPolicy`는 기준일·근거 상태·출처·정보 가용 시각·시장·유형·상장 상태를 확인한다. 유형만 보완해도 `ELIGIBILITY_CONFIRMED`가 되는 구조가 아니다. 적용 기준일이 없으면 `AS_OF_DATE_UNVERIFIED`가 먼저 반환되며, 자료를 통과시키기 위해 날짜나 `AS_OF_VERIFIED`를 채우지 않는다. `CURRENT_ONLY`는 실제 현재 관측을 확인한 자료에 대한 범위이지 이번 명세 열람만으로 생성할 데이터 상태가 아니다.

## 승인 후 최소 실측 범위

후속 실측은 **이용 조건·API 승인·기준일과 예산을 확인한 뒤 명시적으로 요청받은 별도 작업**이다. 이번 문서가 실행 권한이나 수집 완료를 뜻하지 않는다.

첫 실측은 기준일 하나를 고정하고 KOSPI·KOSDAQ 종목기본정보를 각각 최대 한 번, 총 2회 요청하는 범위를 제안한다. 이는 프로젝트의 관측 예산이지 전체 목록이 두 요청으로 완성된다는 제공자 보장이 아니다. 분할·잘림·누락이 있으면 불완전 관측으로 보존하고 페이지 추가·기간 확대·재시도는 자동으로 하지 않는다. 해당 키의 다른 API 사용량과 추가 한도도 함께 확인한다.

요청 서비스·방식·기준일·수집 시작과 완료·상태·원본 응답 바이트·해시·규격 참조를 새 관측으로 보존하되 인증키와 전체 인증 헤더는 저장·로그에 남기지 않는다. 실제 유형 값의 공식 정의, 코드 중복·식별 연결·누락 건수와 KIS 원문의 불변성을 확인한 뒤에만 보완 정책을 검토한다.

비교 대상으로는 보통주·우선주와 미확인 `ST/SPACE/9`, 영숫자 단축 코드 등 기존 KIS 관측 사례를 활용할 수 있다. 원천에 해당 사례가 없으면 억지 표본을 만들지 않고 연결 불가로 기록한다. 비교 가능한 관측 범위를 먼저 확인하며 과거 KRX 기준일에 현재 KIS 전체 목록을 붙여 과거 자격 검증으로 사용하지 않는다. 의미·범위·완전성·시점 중 필수 근거가 없으면 보완 결과를 승인하지 않는다.

## 로컬 보존과 검증 결과

공개 자료는 Git 제외 경로 `build/stock-eligibility-krx-source-validation-01/`에 보존했다. `source-capture.json`은 공식 HTML 5개와 DOCX 원본 2개의 URL·수집 시각·크기·SHA-256을 기록한다. 성공한 보존 실행의 시각은 `2026-10-05T12:35:53.7500151+00:00`부터 `2026-10-05T12:36:05.9958799+00:00`까지다. 이 시각을 종목 데이터 수집·공개 시각으로 사용하지 않는다.

| 원본 명세 | bytes | SHA-256 |
| --- | --- | --- |
| `kospi-spec.download` | 6,759 | `a74eeff31f3e0a5297836c606604ba04c30268eeea03e7290e941d6874a53892` |
| `kosdaq-spec.download` | 6,760 | `f0a89b6dacb1072e65889412da9670990192b0256dd82089867ce4d17e30de8a` |

`.download`는 로컬 보존 확장자이며 공식 응답의 파일명은 두 파일 모두 `Spec.docx`다. 원본을 수정하지 않고 `word/document.xml`을 구조적으로 읽어 요청·응답 표를 대조했다. 공식 페이지가 공개하는 base64 XML도 디코딩한 바이트 그대로 `kospi-public-schema.xml`과 `kosdaq-public-schema.xml`로 보존했다. DOCX의 시각적 레이아웃을 검증하거나 새 Word 문서를 만든 작업은 아니다.

`verify-specifications.ps1`은 네트워크 없이 원본 7개의 크기·해시, 시장별 명세 버전, 요청 필드 1개와 응답 필드 12개의 이름·유형·설명 및 두 시장 계약의 일치를 확인했다. 응답 예제가 자리표시자라는 점도 검사했다. 헬퍼의 DOCX 표 개수 가정을 실제 구조에 맞게 수정한 뒤 성공했으며 원본은 변경하지 않았다. 결과는 `local-verification.json`, 검증 시각은 `2026-10-05T12:42:20.2638540+00:00`다. `source-capture.json`의 SHA-256은 `fae5de887640fe4372eae5d231fbc766601ed0874cb15c4f917e786a468338e9`다.

성공한 보존 실행은 공개 문서 GET 7회다. 사전 HTML 열람·웹 검색·웹 도구의 다운로드 실패와 초기 보존 요청의 500 응답 1회는 이 횟수에 포함하지 않는다. 첫 500 응답 후 읽기에 성공했던 PowerShell 방식으로 변경했으며 로그인·데이터 API로 우회하지 않았다. 실제·샘플 데이터와 인증 요청은 모두 0회다.

이번 변경은 이 문서와 기존 문서의 후속 안내·링크로 제한한다. Java·설정·스키마·테스트를 변경하지 않아 Gradle 테스트는 재실행하지 않았다. 기존 KIS 원본·DB·Docker·계좌·주문·OpenAI를 변경하거나 호출하지 않았고 커밋·Push도 하지 않았다. 공개 명세의 일치와 해시 보존은 실제 데이터 값·종목 자격·과거 모집단·이용 허가 검증을 대신하지 않는다.

## 후속 실측 사전점검

[최소 실측 사전점검](stock-eligibility-krx-source-validation-02.md)은 KIS·KRX 보존 자료의 불변성을 확인했지만 인증키 설정·API 승인·이용 범위·기준일이 확인되지 않아 데이터 요청을 보내지 않았다. 실제 유형 값·식별 대조·과거 자격 검증은 여전히 미완료다.
