# 종목 자격 데이터 원천 검증과 수집 범위

## 판정과 범위

2026-10-05 KIS 공식 종목 마스터 규격과 정제 예제를 대조했다. **종목 코드·유형·상장일 등의 필드 의미는 확인했지만, 과거 기준일의 시장 소속·상장 상태와 당시 정보 가용성을 검증한 것은 아니다.** KIS 현재 마스터는 현재 관측 자료를 보존하기 위한 첫 수집 원천으로 사용하되, 그 자료만으로 과거 종목 자격을 승인하지 않는 방향으로 정한다.

현재 통합 후보 평가는 명시한 자격 입력과 DB 일봉을 평가·저장할 수 있다. 그러나 [MySQL 실측 검증](stock-candidate-evaluation-observation-01.md)의 자격 근거 누락과 `CURRENT_ONLY` 대조는 실제 종목 원천의 검증이 아니다. 현재 생존 종목 목록을 과거 모집단으로 사용하면 상장폐지 종목이 빠지고 후보 성과가 과장될 수 있으므로, 저장·복원 성공과 원천 적격성을 구분한다.

이번에는 공개 문서와 기존 코드만 읽었다. 실제 마스터 ZIP 다운로드·원본 행 대조·파서 실행·DB 연결·Docker 조작·KIS 및 OpenAI API 호출은 하지 않았다. Java·설정·스키마·테스트·원본 증거를 변경하지 않았다. 아래 매핑과 수집 조건은 **후속 구현의 범위와 검증 기준**이지 구현 완료 보고가 아니다. `DESIGN_ONLY`와 `runtimeSelectionImplemented=false`를 유지한다.

## 기존 입력과의 연결

현재 입력은 `com.stock.strategy.universe.eligibility.input.StockEligibilityInput`이며 외부 원천 조회 기능은 없다. 다음 표는 확인한 필드 의미를 기존 입력에 어떻게 연결할지 정리한 것으로, 자동 변환 코드를 추가하지 않는다.

| 기존 입력 | 연결 방향 | 현재 남은 한계 |
| --- | --- | --- |
| `symbol` | `mksc_shrn_iscd`를 문자열로 보존한다. 표준 코드와 원본 필드도 함께 보존해 대조한다. | 실제 행의 공백·코드 형식을 아직 대조하지 않았다. 숫자 변환·임의 0 채우기·잘라내기를 하지 않는다. |
| `market` | 출처와 형식이 확인된 `kospi_code.mst`·`kosdaq_code.mst`의 파일 구분을 현재 시장 관측값에 연결한다. | 현재 파일 소속이 과거 시장 소속이나 시장 이전 이력의 증거는 아니다. KRX·NXT 조회 범위와도 다르다. |
| `securityType` | 증권 그룹·ETP 구분·우선주 구분을 함께 확인해 아래 매핑 초안을 적용한다. | 실제 코드 조합·상충 값의 처리와 시장별 차이는 파서 구현 전에 검증해야 한다. |
| `listingStatus` | 해당 기준일의 상장 상태를 입증한 경우에만 값을 넣는다. | 마스터에 행이 있다는 사실과 상장일만으로는 승인하지 않는다. 누락된 행을 `NOT_LISTED`로 만들지 않는다. |
| `asOfDate` | 시장·유형·상장 상태가 적용되는 날짜를 확인한 경우에만 넣는다. | 요청 기준일·다운로드 날짜·상장일을 복사하지 않는다. 적용일 근거가 없으면 null이다. |
| `sourceReference` | 원본·사용 규격·수집 기록을 찾을 수 있는 고정된 관측 참조를 사용한다. | URL이나 해시 문자열이 있다는 것만으로 원천의 진위·과거 정합성이 인증되지는 않는다. |
| `informationAvailableAt` | 전달하는 판정 항목 전체의 가용 시각이 확인된 경우에만 넣는다. 여러 시각이면 가장 늦은 값을 사용한다. | 수집 시작·완료 시각이나 파일 수정 시각을 당시 공개 시각으로 대체하지 않는다. |
| `evidenceStatus` | 현재 관측만 확인한 자료는 `CURRENT_ONLY`, 출처·형식도 불확실하면 `UNVERIFIED`로 남긴다. | 공식 URL·파싱 성공만으로 `AS_OF_VERIFIED`를 만들지 않는다. |

`stck_lstn_date`는 상장일 필드이지 상장폐지일·전체 유효 기간이 아니다. `base_date`는 규격상 기준년월이며 마스터 전체의 적용일·공개 시각이라는 근거는 확인하지 못했다. 거래정지 `trht_yn`과 정리매매 `sltr_yn`도 미상장 상태와 같은 개념이 아니다. 이 구분은 [KOSPI 규격](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/%EC%A2%85%EB%AA%A9%EB%A7%88%EC%8A%A4%ED%84%B0%EC%A0%95%EB%B3%B4%28%EC%BD%94%EC%8A%A4%ED%94%BC%29.h)과 [KOSDAQ 규격](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/%EC%A2%85%EB%AA%A9%EB%A7%88%EC%8A%A4%ED%84%B0%EC%A0%95%EB%B3%B4%28%EC%BD%94%EC%8A%A4%EB%8B%A5%29.h)을 기준으로 한다.

### 유형 매핑 초안

공식 코드는 원천의 의미이며, 우리 enum으로 묶는 방식은 프로젝트의 설계 선택이다. 다음 초안은 **현재 관측 유형의 분류**에만 해당한다. 실제 행과 필드 조합을 검증하기 전에는 자동 평가에 연결하지 않는다.

| 확인한 원천 값 | 프로젝트 매핑 방향 |
| --- | --- |
| 증권 그룹 `ST`는 주권, ETP `0`은 해당 없음, 우선주 `0`은 보통주 | 세 값과 다른 관련 항목이 상충하지 않는 경우 `COMMON_STOCK` 후보로 해석한다. 우선주 `0` 하나만 보고 보통주로 만들지 않는다. |
| `ST`, ETP `0`, 우선주 `1` 또는 `2` | 구형·신형 우선주를 `PREFERRED_STOCK` 후보로 묶는다. |
| 증권 그룹 `EF` 또는 `FE` | ETF·해외 ETF를 `ETF` 후보로 묶되, 다른 분류 필드와 상충하면 미확인으로 남긴다. |
| ETP `3` 또는 `4` | ETN·손실제한 ETN을 `ETN` 후보로 묶는다. 증권 그룹과의 실제 조합·우선순위는 아직 확인하지 않았다. |
| KOSPI ETP `5` | 상장형 수익증권이라는 설명은 확인했다. 개별주로 분류하지 않으며 프로젝트 유형은 `OTHER`로 분류하는 방향이다. |
| 알 수 없는 코드·빈 값·상충 조합 | null과 원문을 보존한다. 보통주나 확정 제외 유형 `OTHER`로 추정하지 않는다. |

KOSPI의 ETP 설명에는 `5`가 있으나 열람한 KOSDAQ 규격에는 없다. KOSPI 설명을 KOSDAQ에 그대로 확장하지 않는다. 다른 증권 그룹의 상세 매핑과 SPAC·거래정지·관리종목의 추가 제외 정책도 이번에 확정하지 않는다. 기존 요청은 ETF·ETN을 허용하지 않지만, 원천 값을 읽었다는 사실만으로 모든 시점 근거 검사를 건너뛰어 `INELIGIBLE`을 만들지는 않는다.

현재 `StockEligibilityPolicy`는 적용 기준일을 먼저 확인하고 그 다음 `CURRENT_ONLY`를 검사한다. 따라서 현재 자료의 `asOfDate`를 비워 두면 최초 사유는 `AS_OF_DATE_UNVERIFIED`다. 모든 현재 자료가 반드시 `CURRENT_INFORMATION_ONLY`로 기록된다고 기대하거나, 그 사유를 만들려고 날짜를 채우지 않는다. 필요한 근거가 없으면 통합 평가의 `INCOMPLETE`가 올바른 결과다.

## 현재 관측과 과거 검증의 분리

첫 수집에서 보존할 것은 원본 ZIP·추출 파일과 원문 행, 시장별 출처 URL, 원본·추출 파일 해시, 사용 규격·파서 버전, 인코딩·레이아웃, 수집 시작·완료 시각 및 전체·성공·미확인·오류 건수다. 파일과 관측 참조를 덮어쓰지 않고 새 수집 배치로 보존한다. 이는 **동일 자료로 재현하기 위한 계약**이며 아직 저장 위치·Entity·DB 스키마를 구현하거나 확정하지 않았다.

수집 시각, 자료의 적용 시점, 정보가 알려진 시각은 따로 다룬다. 지금부터 원본을 쌓으면 앞으로 관측한 시점의 근거는 늘릴 수 있지만, 수집 전 과거를 소급해 검증하거나 관측 사이의 변화를 자동으로 복원할 수는 없다. 원본 해시는 무변경 대조 수단이지 과거 정보 가용성의 증거가 아니다.

과거 백테스트에 자격 입력을 사용할 때는 다음 근거가 별도로 필요하다.

1. 선정 기준일에 상장돼 있었던 전체 대상과 이후 상장폐지 종목을 포함한 당시 모집단의 범위.
2. 상장·상장폐지·시장 이전·종목 유형 변경의 적용 시점과 상태 변화 이력.
3. 해당 정보의 공개·가용 시각과 정정 이력. 현재 정정본만으로 당시 값을 대체하지 않음.
4. 각 항목을 같은 종목에 연결할 식별 근거와 누락·상충 자료의 처리 기록.

열람한 규격과 예제만으로는 위 근거를 확보하지 못했다. 추가 자료가 없으면 현재 관측 또는 근거가 확인된 제한된 대상만 연구 범위로 명시하고, 과거 전체 시장을 검증했다고 주장하지 않는다. `AS_OF_VERIFIED`는 계속 호출자의 확인 선언이며 이 문서도 그 선언을 대신하지 않는다.

## 첫 수집의 최소 범위

후속 구현은 **명시적으로 실행한 수동 수집 한 회에서 KOSPI·KOSDAQ 파일을 각각 최대 한 번 가져와 원본과 해석 결과를 대조하는 범위**로 제한한다. 자동 재시도·정기 스케줄·종목별 API 조회·운영 Universe 교체·백테스트 또는 주문 연결은 하지 않는다. 첫 결과가 불완전해도 완료 상태를 만들려고 대상이나 근거를 바꾸지 않는다.

수집 전에는 다음 조건을 고정한다.

| 항목 | 조건 |
| --- | --- |
| 다운로드 | 공식 HTTPS 출처와 최종 응답 출처를 확인하고 TLS 인증서 검증을 유지한다. 시간 제한·응답 및 압축 해제 크기 한도는 실제 실행 전에 명시한다. |
| 압축 해제 | 예상 파일만 허용하고 경로 이탈·추가 엔트리·과도한 크기를 거절한다. 예제의 무제한 `extractall()`을 그대로 재사용하지 않는다. |
| 형식 | 시장별 인코딩·필드 폭·줄바꿈·실제 레코드 길이를 원본으로 검증한다. 예제의 문자열 슬라이스를 생산 환경의 바이트 오프셋 계약으로 단정하지 않는다. |
| 식별·중복 | 코드의 앞자리 0과 표준 코드를 보존한다. 동일 파일 및 시장 간 중복·식별 충돌을 보고하고 임의 병합하지 않는다. |
| 누락·오류 | 디코딩 실패·잘못된 날짜·필드 누락·알 수 없는 코드·상충 조합의 원문과 건수를 남긴다. 구조 오류는 수집 검증 실패, 의미 미확인은 미확인 결과로 구분한다. |
| 보존·비교 | ETF·ETN·미확인 행도 원본에서 지우지 않는다. 전체 행이 성공·미확인·오류 건수로 설명되고, 보존한 동일 원본의 재해석 결과가 일치해야 한다. |

[KOSPI 예제](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/kis_kospi_code_mst.py)와 [KOSDAQ 예제](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/kis_kosdaq_code_mst.py)는 TLS 인증서 검증을 해제하고 ZIP을 일괄 추출한다. 예제는 필드 해석의 참고 자료이며 이 보안 동작을 구현 지침으로 채택하지 않는다. 출력 Excel이나 파싱 결과만 남기는 것도 원본 보존을 대신하지 못한다.

## 완료 조건과 남은 확인

이번 문서 작업의 완료 조건은 필드 의미·매핑 방향·미확인 시점 근거·첫 수집 범위를 구분하고 기존 평가 계약에 연결하는 것이다. 공개 예제 열람을 실제 파일 검증, 종목 자격 완료 또는 수익성 검증으로 표시하지 않는다.

후속 첫 수집은 두 원본의 형식·건수·식별·코드 조합과 재해석 일치를 확인하는 별도 검증이다. 합성 파서 테스트가 통과해도 실제 원본 대조와 과거 증거를 대신하지 않는다. 다운로드·형식·조합 검증이 실패하면 자료를 평가에 연결하지 않고 원인을 기록한다. 과거 근거가 계속 없으면 `DATA_UNVERIFIED`·`INCOMPLETE`를 유지한다.

원천 제공자에게 추가로 확인할 질문은 다음과 같다. 이번에 문의를 발송하거나 답변을 받은 것은 아니다.

1. 두 마스터의 갱신·적용 시점과 공개 시각을 확인할 수 있는 규격 또는 기록이 있는가?
2. 과거 파일·상장폐지·시장 이전·유형 변경과 정정 이력을 제공하는 경로가 있는가?
3. 과거 모집단의 완전성을 확인할 방법과 증권 그룹·ETP·우선주 코드의 허용 조합이 있는가?

별개로 [일봉 거래대금 원천 검증](../../../market/price/history/validation/daily-price-trading-value-source-validation-01.md)의 단위·세션 범위·가용성 미확인도 남아 있다. 자격 원천을 보완했다고 유동성 원천이나 전략 순성과까지 승인하지 않는다. 이번 작업에서는 Java 테스트를 재실행하지 않고 문서 경로·링크와 변경 범위를 확인한다.
