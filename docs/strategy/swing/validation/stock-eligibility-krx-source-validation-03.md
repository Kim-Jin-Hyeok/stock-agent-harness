# KRX 종목기본정보 실응답 관측 및 KIS 식별 대조

후속 [KRX 현재 유형 해석 정책](../../../market/stock/master/krx-stock-basic-info-type-classification.md)에서 이 관측의 원문을 재사용해 제한적인 유형 해석과 보류를 구현했다. 아래 내용과 고정 증적은 최초 실응답 관측 결과이며 당시 상태·원문·해시를 변경하지 않는다. 후속 정책도 종목 자격이나 과거 모집단을 승인하지 않는다.

## 현재 상태

2026-10-06 사용자가 확정한 기준일 `2026-10-02`로 KRX 유가증권·코스닥 종목기본정보를 각각 1회 조회했다. **두 요청 모두 HTTP 200이며, 기존 파서로 읽은 총 2,766행 전부가 보존된 KIS 자료의 표준 코드·단축 코드·시장과 일치했다.** 추가 API 호출 없이 같은 원문을 재분석해 결과 재현성과 원본 불변성을 확인했다.

현재 상태는 `OBSERVED_PARSED_AND_REPLAY_VERIFIED_NOT_TYPE_APPROVED`다. 이번 결과는 현재 원천의 식별 연결 관측이며 유형 해석·종목 자격·과거 모집단 승인이 아니다. 앞선 [사전점검](stock-eligibility-krx-source-validation-02.md)과 이번 작업의 최초 준비 증적은 덮어쓰지 않는다.

| 항목 | 확인 결과 |
| --- | --- |
| 로컬 키 설정 | 키를 헤더에만 사용해 두 실제 엔드포인트의 조회 성공. 값은 출력·기록하지 않음 |

| KRX 응답 행 수·정확한 식별 일치 | 각각 2,766행 |

`2026-10-02`는 프로젝트 거래일 달력에서 10월 5일 휴장을 제외한 직전 완료 거래일로 제안한 뒤 사용자가 확정했다. 해당 날짜로 응답을 받았지만 전체 모집단·과거 정보 가용성까지 검증한 것은 아니다. 개인 연구용 신청을 실제 자동매매나 제3자 제공 권한으로 확대 해석하지 않는다.

## 실응답 결과

조회는 한국시간 2026-10-06 11:18:26부터 11:18:32 사이에 수행했다. 두 응답의 Content-Type은 `application/json; charset=utf-8`이며 원문 바이트를 보존했다. 기존 파서의 `OutBlock_1`과 12개 문자열 필드 검사를 모두 통과했다.

| KOSPI | 200 | 3,331 ms | 278,289 bytes | 942 | 942 | 1,636 |
| KOSDAQ | 200 | 2,735 ms | 562,407 bytes | 1,824 | 1,824 | 1 |
| 합계 | 양쪽 성공 | 시장별 순차 조회 | 840,696 bytes | 2,766 | 2,766 | 1,637 |

보존된 KIS 자료는 KOSPI 2,578행, KOSDAQ 1,825행, 총 4,403행이다. KRX 행에는 식별자 공백·중복·표준 코드 미연결·단축 코드만 일치·단축 코드 불일치·시장 불일치가 각각 0행이다. 시장 간 식별 중복도 없었다. KRX 원문 `MKT_TP_NM`은 요청 시장과 같은 `KOSPI` 942행, `KOSDAQ` 1,824행으로 관측했다.

정확히 연결되지 않은 KIS 1,637행은 별도 목록으로 보존했다. 그중 1,159행은 기존 KIS 정책에서 이미 ETF로 해석하던 `KOSPI/EF/2/0`이다. 나머지는 다른 원문 조합으로 남겼고, KOSDAQ의 미연결 1행도 포함한다. 서비스 상품 범위나 적용 시점이 같은지 확인되지 않았으므로 잔여 행을 데이터 누락·상장폐지·거래 불가 중 어느 하나로 자동 판정하지 않는다.

## 관측 도구

이번 도구는 운영 Client나 Provider가 아니라 Git에서 제외된 로컬 관측용이다. Spring 애플리케이션에 등록하지 않는다.

| 파일 | 책임 |

| `build/stock-eligibility-krx-source-validation-03/observe.ps1` | 키의 안전한 로딩, 보존 증적 검사, 사전조건 검사, 명시적으로 허용된 수집 |

Java 도구의 패키지는 `com.stock.tools.market.stock.master.krx`다. 운영 소스의 `com.stock.market.stock.master.provider.krx.parsing.KrxStockBasicInfoParser`와 `StockMasterBatchParsingService`를 그대로 사용한다. Java 도구에는 인증키 읽기·네트워크·DB 접근 기능이 없다.

도구와 증적은 이 작업공간에만 존재하며 일반 Git 커밋에 포함되지 않는다. 다른 작업공간에 자동으로 설치되는 기능이 아니다. `gradlew clean`으로 `build/`가 삭제되면 함께 사라지므로 증적을 유지할 동안에는 실행하지 않는다. Git 제외는 암호화나 이용권한을 대신하지 않는다.

## 실제 요청 제한

수집 기본값은 꺼져 있다. `-Collect`, 명시적인 `-BasDd`, `-ApiApprovalsConfirmed`, `-UsageScopeConfirmed`를 모두 지정해야 요청 단계로 진입한다. 확인 플래그는 승인 증명이나 법률 판단이 아니라 사용자 선언이다. 이번에는 사용자가 확정한 날짜와 개인 연구용 신청 목적의 범위에서 실행했다.

수집 대상은 공식 개발 명세에서 확인한 다음 두 경로로 고정한다.

- 유가증권: `https://data-dbg.krx.co.kr/svc/apis/sto/stk_isu_base_info`
- 코스닥: `https://data-dbg.krx.co.kr/svc/apis/sto/ksq_isu_base_info`

[유가증권 공식 안내](https://openapi.krx.co.kr/contents/OPP/USES/service/OPPUSES002_S2.cmd?BO_ID=PiwgMdTwmsenXhmqqxuj)와 [코스닥 공식 안내](https://openapi.krx.co.kr/contents/OPP/USES/service/OPPUSES002_S2.cmd?BO_ID=CifLHplnUFMgpHIMMPXs)를 기준으로 한다. 공개 샘플에서 확인한 GET 방식을 첫 실측에 사용했고 두 실제 엔드포인트 모두 성공했다. 이번 성공이 다른 날짜·오류·페이지·Rate Limit 등 모든 HTTP 계약의 검증은 아니다.

같은 `basDd`로 시장별 최대 1회, 총 최대 2회 시도한다. 첫 HTTP 요청이 실패하면 두 번째 요청도 중단한다. 자동 재시도·페이지 추가·기간 확대·HTTP 방식 변경·리다이렉트 추적은 하지 않는다. 키는 `AUTH_KEY` 헤더에만 넣고 URL이나 명령 인자에 넣지 않는다.

요청 직전에 시장별 `*-attempt.json`을 생성한다. 기존 요청 흔적 또는 결과가 있으면 재진입을 거절한다. 전송 오류는 서버가 요청을 받았는지 모르는 상태일 수 있으므로 재실행해도 안전하다고 판정하지 않는다.

응답은 문자열로 재직렬화하지 않고 `*-response.bin`에 원문 바이트로 저장한다. HTTP 상태·수집 시작과 종료 시각·소요 시간·응답 크기·SHA-256·본문 완결 여부는 별도 JSON에 남긴다. 32 MiB 크기 제한과 요청·읽기 시간 제한을 적용한다. 오류·부분 응답은 정상 데이터로 취급하지 않으며, 키가 그대로 반사된 본문은 저장하지 않는다.

## 식별 대조 원칙

두 시장의 완결된 성공 HTTP 응답이 있어야 식별 대조를 시작한다. 이번에는 응답 크기와 해시를 확인한 뒤 기존 KRX 파서를 적용했다. 구조가 다른 오류 JSON을 정상 종목 목록으로 받아들이지 않는다.

표준 코드를 정확히 연결하고 단축 코드와 요청 시장을 교차 확인한다. 단축 코드의 앞자리 0·영문자·공백을 임의로 정규화하지 않는다. 중복은 다중 목록으로 보존하며 단일 값으로 덮어쓰지 않는다.

각 KRX 행은 정확한 식별 일치, 식별자 공백, 식별 중복, 표준 코드 미연결, 단축 코드만 일치, 단축 코드 불일치, 요청 시장 불일치 중 하나로 기록한다. 정확히 연결되지 않은 KIS 행도 별도 목록으로 남긴다. 이 잔여 목록은 신규 상장·상장폐지·상품 범위 차이 중 어느 하나로 자동 해석하지 않는다.

KRX의 시장·증권구분·주식종류·소속부 값은 원문 분포로만 기록한다. 요청 시장의 일치와 `MKT_TP_NM`의 의미 검증은 다른 검사다. 유형 enum이나 자격 판정으로 변환하지 않으며 KIS 원문·정책·보류 사유도 바꾸지 않는다.

KIS 자료는 2026-10-05 수집분이다. KRX 요청 기준일과 KIS 수집 시각은 구분한다. 식별자가 일치하더라도 두 자료의 같은 시점 상태나 과거 자격이 입증되는 것은 아니다. `informationAvailableAt`을 요청일 또는 수집 완료 시각으로 채우지 않는다.

## 완료한 검증

- 사전 준비 시 KRX 파서·원문 record·결과 record와 KIS 배치 파서 관련 JUnit 테스트 226개 통과. 실패·오류 0개. 이번 재개에서는 운영 소스를 변경하지 않아 JUnit을 재실행하지 않았다.
- PowerShell 관측 도구 오프라인 검사 16개, Java 식별 대조 도구 검사 15개를 이번 재개에서도 재실행해 통과했다.
- 사전 준비 시 이용 범위가 미확인인 수집 실행이 요청 전에 차단됨을 확인했다. 당시 요청 흔적은 0개였으며 그 점검 결과는 유지한다.
- 실제 조회 이후 수집 재진입 거절 검사 통과. 두 기존 요청 흔적을 보존하고 추가 API 요청은 발생시키지 않았다.
- 기존 KIS 7개 파일과 KRX 공개 자료 7개 파일의 크기·SHA-256 일치 확인.
- 기존 KIS 보존분을 운영 파서로 재처리: KOSPI 2,578행, KOSDAQ 1,825행, 총 4,403행. 재수집 없이 검사 전후 원본 불변 확인.
- 같은 KRX 원문과 KIS 자료로 오프라인 분석을 두 번 수행했다. 분석 시각을 제외한 전체 결과가 동일하고 KRX 원문 해시도 그대로다.
- 관측 도구·원문·분석 보고서 등 로컬 증적에 인증키 값이 포함되지 않음을 확인했다.

실제 TLS 통신과 이번 두 엔드포인트의 성공 응답은 관측했다. 서버 오류 응답·읽기 시간 초과·본문 크기 초과·다른 날짜의 자료·페이지 분할 여부는 실측하지 않았다. 단일 요청이 전체 모집단을 빠짐없이 반환했다는 판정도 하지 않는다.

로컬 증적은 `build/stock-eligibility-krx-source-validation-03/`에 있다. `preflight.json`과 `verification.json`은 확인 대기 당시의 사전 준비 결과를 유지한다. `collection.json`은 실제 두 요청의 결과, `analysis.json`은 기존 파서 결과·식별 대조·잔여 행 전체, `analysis-replay.json`은 오프라인 재현 결과다. `final-verification.json`은 실제 관측 요약·검증 결과와 관련 증적 15개의 크기·해시를 기록한다.

- `preflight.json` SHA-256: `64a3a2edfe8aa81d1a8a2853b2882c01f3b2e176dc163389baf32683435009de`
- `verification.json` SHA-256: `2daf399449bb214a1afacc3cff9380051e156f3aa518385ea3e0276a7f60b008`
- KOSPI 원문 SHA-256: `7914a16e95eb7c1d5002b6e3acb3fa994ddd2f9766c7c59b1542853fad987a84`
- KOSDAQ 원문 SHA-256: `9d84b2e52eb9d83392325e4d3319853fa18848043940bcead74998633d4389e0`
- `analysis.json` SHA-256: `47df3aad3679a6ecc0fed546a24435d753aa791339cc8c037cdc6f5eb4bbcf80`

PowerShell 5.1의 `ConvertFrom-Json`은 분포 키에 빈 문자열이 있는 분석 JSON을 읽지 못했다. 원본이나 파서 결과를 수정하지 않고 .NET `JavaScriptSerializer`로 읽어 빈 키를 보존한 채 요약과 재현 결과를 검사했다. 이 로컬 판독 문제는 KRX 요청 실패나 원문 파싱 실패가 아니다.

## 변경하지 않은 영역

운영 Java 소스·설정·의존성·DB 스키마·종목 후보 선정·백테스트·주문 연결을 변경하지 않았다. `.env`와 Docker 설정도 변경하지 않았고 Docker·KIS·OpenAI API를 호출하지 않았다. 커밋과 Push는 실행하지 않았다.

`DESIGN_ONLY`, `typeInterpretationApproved=false`, `runtimeSelectionImplemented=false`, `eligibilityOrHistoricalPopulationVerified=false`를 유지한다. `crossSourceSamePointInTimeVerified=false`도 유지한다. 조회와 식별 대조를 완료했지만 운영 Provider·종목 자격·실투자 권한을 구현하거나 승인한 것은 아니다.
