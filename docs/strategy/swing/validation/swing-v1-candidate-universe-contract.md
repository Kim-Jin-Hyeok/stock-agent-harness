# SWING_V1 백테스트 후보 Universe 선정·검증 계약

## 목적과 상태

이 문서는 백테스트 후보를 수익률이나 매매 신호를 보고 고르지 않고, 선정 당시 확인할 수 있었던 상장 정보와 유동성으로 재현 가능하게 구성하는 계약이다. 기존 `SWING_V1`의 진입·청산·수량·Risk 규칙은 변경하지 않는다.

```text
contractVersion: 1
contractStatus: DESIGN_ONLY
selectionMode: FIXED_INITIAL_COHORT
runtimeSelectionImplemented: false
```

**선정 계약을 정리한 상태이지 시장 전체 후보 선정이나 확장 표본 검증을 완료한 상태가 아니다.** 유동성 수치와 원천 데이터 출처는 별도 실험 계획에서 결과 확인 전에 확정해야 한다. 필수 조건이 비어 있거나 당시 정보를 검증할 수 없다면 검증용 Universe 실행을 허용하지 않는다.

[슬리피지 관측 07](swing-v1-slippage-observation-07.md)은 이미 본 네 종목의 계산과 비용 민감도를 확인했다. 작은 순이익이나 보유 비교 우위가 비용 증가로 사라졌으며, 시장 대표 표본·미사용 기간·양의 기대수익을 입증한 결과가 아니다. 다음 확장 실험에서도 손실과 무거래를 포함하고, 기존 관측을 이 계약으로 선정한 결과라고 재분류하지 않는다.

## 현재 코드와 경계

| 현재 구조 | 역할과 한계 |
| --- | --- |
| `StrategyStockUniverseRegistry` | 운영 설정의 전략별 종목 목록을 반환한다. 시장 전체 검색이나 유동성 선정을 하지 않는다. |
| `SwingV1BacktestExperimentRequest.candidateSymbols` | 백테스트에 사용할 명시적인 후보와 순서를 받는다. 운영 후보를 자동으로 가져오지 않는다. |
| `SwingV1BacktestExperimentService` | 후보마다 같은 초기 현금의 독립 포트폴리오를 평가한다. 하나라도 실패하면 성공한 종목만 남기지 않는다. |
| `DailyPriceBar`, `DailyPriceBarEntity` | OHLCV와 nullable 거래대금·조회 시장 범위를 보관한다. 기존 행은 새 값이 `null`이며 과거 상장 상태·종목 유형·제공 시점 이력은 없다. |
| 현재 관측 원본 | 소규모 고정 표본이다. 과거 시장 전체 구성이나 당시 제공된 데이터 버전의 증거를 대신하지 않는다. |

후보 선정 계약은 여전히 문서 설계 단계다. 일봉 거래대금 저장 경로가 추가되어도 종목 마스터·선정 서비스·평균 계산·자동 선정은 구현되지 않았다. 운영 후보·주문·스케줄·Risk·AI Prompt는 바꾸지 않는다.

검증 표본을 선정하는 Universe와 거래마다 신호를 거르는 전략 Screener는 구분한다. 이 계약은 첫 평가 전 표본을 정하는 전자만 다룬다. 골든크로스·ATR·과거 전략 수익률로 후보를 선정하거나 운영 BUY 조건에 유동성 필터를 삽입하지 않는다.

### 일봉 거래대금 저장 경로

- `KisDailyPriceBarOutput.accumulatedTradingValue`는 기간별 시세 응답 `output2`의 `acml_tr_pbmn`을 읽는다. 기존 일봉 API 응답을 사용하며 거래대금 전용 호출을 추가하지 않는다.
- `DailyPriceBar.tradingValueKrw`와 DB `trading_value_krw`는 nullable `Long`/`BIGINT`다. 숫자 `0`은 확인된 0으로 보존하고, 필드 누락·`null`·공백은 미확인 `null`로 보존한다. 음수·숫자가 아닌 값·`Long` 범위 초과는 Provider의 영구 입력 실패로 처리한다. 종가 × 거래량으로 대체하지 않는다.
- 저장 계약은 응답 정수를 배율 적용 없이 `tradingValueKrw`에 보존한다. **공식 명세에서 누적 거래대금 필드·일봉 주기·시장 코드는 확인했지만 이 필드의 원 단위 배율과 시간외 포함 범위는 명시적으로 확인하지 못했다.** `Krw`라는 필드명이나 테스트 성공이 원천 단위 검증을 대신하지 않는다. 실제 유동성 계산에 사용하기 전에 동일 종목·일자·시장 범위의 공식 거래대금과 대조하고, 검증 결과·배율·세션 범위를 실험 원천 계약에 고정해야 한다.
- `TradingVenueScope`는 Broker에 의존하지 않는 `com.stock.market.price.history`의 enum이다. `KRX`, `NXT`, `INTEGRATED`를 사용한다. KIS Client가 실제 요청하는 `J`, `NX`, `UN`과 명시적으로 대응하며 DB에는 enum 이름을 문자열로 저장한다. 이 값은 **요청한 조회 범위**이며 KOSPI/KOSDAQ 소속, 과거 시장의 구성이나 세션 확정 여부를 증명하지 않는다.
- `DailyPriceBarEntity.toBar()`, 기존 DB 조회 서비스와 `HarnessDailyPriceBarSnapshot.from()`은 거래대금과 범위를 그대로 전달한다. 구 생성자와 구 JSON에서 새 필드가 없으면 두 값 모두 `null`이다. 새 스냅샷도 이 구분을 보존한다. 현재 설정을 과거 행에 대입하지 않는다.
- `V4__add_daily_price_trading_value.sql`은 두 nullable 컬럼만 추가한다. 기존 OHLCV·고유키는 유지한다. 저장 단위는 아직 `(symbol, trading_date)`이므로 같은 날짜의 여러 시장 범위를 동시에 저장하는 구조가 아니며 범위가 다른 기간을 검증 없이 합산하지 않는다.
- 증분 수집 서비스는 최신 저장일 이후만 조회한다. 이미 저장된 과거 거래대금이 `null`이어도 자동 재조회하지 않는다. 과거 데이터 보충은 호출 예산·범위·기존 값 충돌 정책을 확정한 별도 작업이다. 이 저장 변경은 과거 재수집, 실 DB 마이그레이션 적용이나 모의투자 서버 재시작을 포함하지 않는다.

원천 확인: [KIS 기간별 시세 공식 명세](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice), [KIS 공식 요청 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py), [KIS 공식 응답 필드 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/chk_inquire_daily_itemchartprice.py). 확인일은 `2026-10-03`이며 실 Broker 호출 없이 공개 명세를 열람했다.

## 선정 시점과 대상

### 기준 시점

- `T`: 첫 판단·체결 평가 거래일. 초기 일봉 근사에서는 첫 신호일의 다음 거래일이다.
- `S`: `T`의 직전 거래일이자 첫 신호 기준일이다. 일봉 입력은 `S`까지 확정된 값만 사용한다.
- `selectionCutoffAt`: 선정 정보가 알려져 있어야 하는 시각. `S` 일봉 확정 이후이고 첫 판단 시각보다 앞서거나 같아야 한다. 날짜만이 아니라 시간대가 있는 시각을 보존한다.
- `selectedAt`: 현재 시스템에서 선정을 계산한 시각. 과거 데이터의 의미상 기준 시각인 `selectionCutoffAt`와 구분한다.

휴장일을 고려한 직전·다음 거래일을 사용하며 단순히 날짜에서 하루를 빼거나 더하지 않는다. 일봉 날짜가 `S` 이전이어도 해당 값이나 상장 정보가 선정 기준 시각 이후에야 알려졌다면 과거 판단의 입력으로 자동 인정하지 않는다.

현재 수집 시각이 과거 기준 시각보다 늦다는 사실만으로 과거 자료를 모두 거절하지는 않는다. 당시 상장 구성과 당시 알려진 정보임을 입증하는 원천 자료·적용 시점·정정 이력을 별도로 확인해야 한다. 현재 종목 목록에 과거 날짜만 붙이거나 현재 수정된 일봉의 날짜만 확인한 것으로 이 검증을 대신하지 않는다. 원본 해시 고정은 재실행 증거이지 과거 정보 가용성의 증거가 아니다.

### 시장과 종목 유형

대상 시장은 KOSPI와 KOSDAQ의 개별주다. 보통주·우선주 등 세부 허용 유형은 `eligibleSecurityTypes`로 실행 전에 명시하며 암묵적으로 확대하지 않는다. ETF·ETN은 허용하지 않는다. 시장·유형·상장 상태를 확인할 수 없는 종목은 일반 주식으로 추정하지 않는다.

상장 구성은 `S` 당시의 자료를 사용한다. 그때 상장되어 있었지만 이후 상장폐지된 종목도 검토 모집단에 남겨야 한다. 나중에 상장된 종목은 초기 모집단에 넣지 않는다. 현재 생존 종목만 제공하는 원천 자료로는 과거 전체 시장을 재구성했다고 주장할 수 없다.

KOSPI 후보는 KOSPI 벤치마크, KOSDAQ 후보는 KOSDAQ 벤치마크의 별도 실험으로 평가한다. 현재 요청에는 벤치마크 하나만 있으므로 두 시장을 한 요청에 섞지 않는다. 시장 매핑은 향후 선정 자료에서 검증해 명시적으로 전달해야 하며 현재 자동 매핑 기능이 있다는 뜻은 아니다.

기준 시점의 거래정지 여부 등 추가 자격 제한을 적용한다면 원천 근거와 규칙을 사전에 고정한다. 이후 거래정지·상장폐지·시장 이전을 미리 알고 제외해서는 안 된다.

## 유동성 계산과 정렬

초기 기준은 **선정 기준일까지의 최근 N개 거래일 평균 거래대금**이다. N, 최소 평균 거래대금과 최대 후보 수는 이번 문서에서 임의의 기본 숫자로 정하지 않는다. 확장 실험의 입력 계약에서 빠짐없이 확정한다.

| 필수 항목 | 계약 |
| --- | --- |
| `lookbackTradingDays` | 양의 정수 N. 달력 일수가 아니라 거래일 수다. |
| `minimumAverageTradingValueKrw` | 양의 금액. 통화는 KRW이며 기준 충족은 `평균 >= 최소 금액`이다. |
| `maxCandidateCount` | 양의 정수. 기준을 충족한 후보 중 이 수까지 선택한다. |
| `liquidityMetric` | 초기 검증은 실제 일별 거래대금의 평균으로 고정한다. 근사 지표와 혼용하지 않는다. |
| `tradingVenueScope` | 거래대금의 시장 범위. 서로 다른 거래소·통합 범위 값을 혼합하지 않는다. |
| `eligibleSecurityTypes` | 명시한 개별주 유형만 허용하며 ETF·ETN이 포함되면 계획을 거절한다. |

입력은 `S`까지의 마지막 N개 거래일 목록에 대응해야 한다. 누락된 날을 제외해 N보다 작은 분모로 평균을 만들거나, N개를 채우려고 평가 기간의 거래일을 포함하지 않는다. 확인된 0원 거래대금은 0으로 포함하고 누락·알 수 없는 거래대금은 0으로 대체하지 않는다. 음수·중복 날짜·충돌한 원본은 입력 오류다.

```text
averageTradingValueKrw = sum(해당 N개 거래일의 실제 거래대금) / N

자격 조건과 유동성 최소 기준 통과
-> 평균 거래대금 내림차순
-> 동률이면 symbol 문자열 오름차순
-> 앞에서 maxCandidateCount개 선택
```

비교와 정렬에는 표시용 반올림 값을 사용하지 않는다. 금액 합산은 오버플로 없이 계산하고, 같은 N을 사용하는 후보의 평균 비교는 정확한 합계로도 가능하다. 종목 코드는 앞자리 0을 보존한 문자열로 취급한다. 중복 종목·빈 코드·시장이나 유형의 충돌은 중단 사유이며 DB 조회 순서에 따라 선택 결과가 바뀌면 안 된다.

현재 일봉의 `volume`은 주식 수량이며 거래대금이 아니다. `closePriceKrw * volume`도 실제 거래대금과 같다고 가정하지 않는다. 별도의 근사 지표를 연구하려면 계산 방식·가격과 거래량의 조정 기준·원천 범위를 고정한 새 선정 정책으로 기록한다. 실제 거래대금이 없다고 기존 기준에 이 값을 조용히 대입하지 않는다. 유동성 기준을 통과해도 실제 주문의 체결 품질을 보장하지 않는다.

## 고정 후보와 데이터 부족

최초 구현은 기간 시작에 한 번 선정하고 끝까지 유지하는 `FIXED_INITIAL_COHORT`다. 기간 중 신규 상장, 유동성 순위 변화나 성과를 보고 후보를 보충하지 않는다. A·B·C처럼 시작일이 다른 실험은 각 시작 시점의 자료로 따로 선정할 수 있지만, 결과를 확인한 뒤 이전 기간의 후보를 수정하지 않는다.

이 방식은 **시작 시점의 선정 종목 집단**을 검증한다. 평가 기간 동안의 전체 시장을 매일 재구성하는 동적 Universe가 아니다. 정기 재선정이나 보유 종목 퇴출·교체는 현재 백테스트의 범위 밖이며 별도 운용 계약이 필요하다.

### 선정 당시 이력 부족

선정 계획에는 `requiredPreselectionBarCount`를 고정한다. 현재 관측과 같은 최근 120개 이력을 사용할 실험이면 120으로 명시한다. 통합 기술 분석의 최소 61개와 실행에 사용할 조회 수량은 같은 개념이 아니므로 암묵적으로 대체하지 않는다.

첫 신호일까지 이미 확인 가능한 선행 이력이 정해진 수량보다 적으면 `INSUFFICIENT_PRESELECTION_HISTORY`로 기록한다. 이는 선정 당시 알 수 있는 자격 부족이다. 상장 이력이 충분한데 저장 데이터만 부족하거나 출처가 불명확한 경우는 자격 부족으로 확정하지 않고 `DATA_UNVERIFIED`로 구분한다. 과거 자료 보충 여부를 확인하기 전에 성공한 조회 종목만 골라서는 안 된다.

### 선정 후 평가 데이터 누락

후보가 고정된 뒤에는 종료일까지의 일봉 존재 여부, 다음 평가 시가 존재 여부나 관측 수익률로 후보를 삭제·대체하지 않는다. 다음 거래일 시가와 평가 기간 데이터는 실행에 필요한 미래 결과 자료이지 초기 선정 조건이 아니다.

향후 수집은 고정된 후보를 대상으로 할 수 있지만 수집 실패·누락·기간 중 거래정지·상장폐지 때문에 평가를 완료하지 못하면 그 후보와 실패를 보존한다. 검증된 자료를 보충한 뒤 같은 선정 스냅샷으로 재실행하거나, 현재 평가기가 해당 사건을 처리하지 못한다면 실험을 불완전 상태로 남긴다. 마지막 가격을 복사해 임의로 성공한 평가곡선을 만들지 않는다.

현재 실험 서비스는 종목 평가일과 벤치마크 날짜 일치를 요구하며 일부 실패를 제외한 성공 반환을 허용하지 않는다. 이 제한 때문에 전체 실험이 실패해도 선정 후보를 줄여 통과시키지 않는다. 실제 기업행위·상장폐지 정산·정지 기간 처리가 구현되어 있다는 뜻도 아니다.

## 선정 상태와 보존할 증거

선정 대상 전체를 포함·제외·확인 불가로 분류하고, 모집단 수가 분류 건수 합계와 일치해야 한다. 유동성 기준을 통과했지만 최대 후보 수에 걸린 종목도 순위와 사유를 남긴다. 다음 명칭은 향후 저장할 의미의 예시이며 현재 Java enum이나 응답 필드가 아니다.

| 분류 / 사유 | 의미 |
| --- | --- |
| 포함 / `SELECTED` | 자격·유동성 기준을 통과하고 최대 후보 수 안에 든 종목 |
| 제외 / `UNSUPPORTED_SECURITY_TYPE` | 기준 시점에 확인된 ETF·ETN 또는 허용하지 않은 개별주 유형 |
| 제외 / `NOT_ELIGIBLE_AS_OF` | 기준 시점의 시장·상장·사전 확정 자격 조건을 충족하지 않은 종목 |
| 제외 / `INSUFFICIENT_PRESELECTION_HISTORY` | 기준 시점에 확인된 실제 선행 이력의 부족 |
| 제외 / `LIQUIDITY_BELOW_MINIMUM` | 완전한 입력으로 계산한 평균 거래대금이 최소 기준보다 작음 |
| 제외 / `CANDIDATE_LIMIT` | 자격·유동성은 통과했지만 고정 최대 후보 수를 넘은 종목 |
| 확인 불가 / `DATA_UNVERIFIED` | 모집단·유형·상장 상태·시점·이력·거래대금 등의 근거 부족 |

확인 불가 종목을 제외 처리해 과거 시장 전체 Universe가 완성됐다고 주장하지 않는다. 모집단 출처의 완전성 또는 자격 판정에 필요한 자료를 확인할 수 없으면 검증용 선정은 준비되지 않은 상태다. 원천 범위가 좁은 표본을 연구한다면 그 범위와 미확인 건수를 따로 기록하고 시장 전체 검증과 구분한다.

보존할 스냅샷은 다음을 포함한다. 아래 이름은 설계상 의미이며 이번에 저장 기능을 구현하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 계획 | 실험 ID, 선정 정책 ID·버전, 코드 revision, 전략 ID·버전, 시장과 벤치마크 |
| 시점 | `S`, `T`, `selectionCutoffAt`, `selectedAt`, 신호 및 실제 평가 기간 |
| 기준 | 유형, N, 최소 거래대금, 최대 후보 수, 선행 이력 수량, 시장 범위와 추가 자격 제한 |
| 모집단 | 원천 종목 목록, 기준일의 상장·시장·유형, 적용 시점·당시 정보 가용성의 근거 |
| 시세 | 선정용 일봉·거래대금의 날짜·값·단위·조정 여부·출처·자료 버전·수집 시각 |
| 결정 | 포함·제외·확인 불가 전체 목록, 종목별 계산 값·순위·사유, 최종 후보와 순서 |
| 재현성 | 원본 파일과 해시, 선정 입력·결과의 해시, 비교 방식과 검산 결과 |
| 평가 연결 | 초기 자금·비용·Risk·전략 설정, 실행 ID, 성공·실패·무거래 결과 및 입력 스냅샷 참조 |

설정과 원본은 결과 확인 전에 고정하고 이후 수정본은 새 실험 ID로 보존한다. 정정된 데이터나 새 자료를 원본에 덮어써 과거 선정 결과를 바꾸지 않는다. API Key·Secret·토큰과 계좌 접속 정보는 증거에 넣지 않는다. 해시만 남기지 않고 재실행에 필요한 원본도 보존한다.

현재 요청에는 선정 정책·원천 스냅샷 필드가 없다. 초기 연결은 외부 실험 계획과 후보 스냅샷을 보존한 뒤 최종 목록을 `candidateSymbols`에 명시하는 방식으로 가능하다. 현재 서비스가 스냅샷을 자동 저장·검증한다거나 자동 선정 기능이 있다는 뜻은 아니다.

백테스트 표본 변경은 선정 정책과 실험 ID로 구분하고 이전 결과와 섞지 않는다. 기존 `SWING_V1` 정책을 호출하는 표본 선정 때문에 진입·청산 코드를 수정하지 않는다. 향후 운영 Universe 자동 갱신이나 Screener 변경을 실제 주문 흐름에 적용할 때는 기존 전략 실험 문서의 `strategyVersion` 증가 규칙을 따른다.

## 실행 준비 및 검증 기준

확장 평가 전에는 다음 조건을 모두 확인해야 한다.

1. 대상 시장·유형·선정 기준 시점·기간·유동성 수치·선행 이력·비용·Risk와 비교 기준을 확정한다. 필수 값에 숨은 기본값을 사용하지 않는다.
2. 기준 시점 모집단과 필요한 데이터 출처를 확인하고, 생존 편향·시점 정보·수정주가·기업행위의 미검증 범위를 명시한다.
3. 과거 시점 자료를 사용할 수 있는지 확인한다. 자료가 없다면 현재 상장 종목으로 대체하지 않고 검증용 과거 Universe 준비를 중단한다.
4. 고정한 선정 입력으로 후보와 전체 사유 목록을 만들고 독립 검산·재실행을 확인한다. 후보가 비거나 확인 불가 문제가 남으면 검증 완료로 취급하지 않는다.
5. 선정 스냅샷을 고정한 뒤 평가 자료를 준비한다. 이 단계의 데이터 부족이 초기 선정 목록을 바꾸지 않도록 한다.
6. 같은 전략·비용 경로로 전체 후보를 평가한다. 모든 후보를 요청 순서대로 확인하고 실패·무거래도 기록한다.

향후 선정 구현을 검증할 최소 사례는 다음과 같다. 이번 변경에서 테스트 클래스나 실행 결과를 만든 것은 아니다.

| 사례 | 기대 결과 |
| --- | --- |
| 같은 원본·기준, 입력 종목 순서만 변경 | 같은 후보와 최종 순서, 종목별 동일 사유 |
| 평균이 최소 금액과 같음 / 작음 | 각각 유동성 통과 / 제외 |
| 거래대금 동률, 앞자리 0이 있는 코드 | 코드 문자열 순서로 안정적인 후보 선정 |
| 최대 후보 수 초과 | 정해진 순위까지만 포함, 나머지는 `CANDIDATE_LIMIT` |
| 선정 기준일 다음 날짜의 데이터가 입력에 추가됨 | 선정 계산에 사용하지 않으며 후보·사유가 유지됨 |
| 선정 이후에 발표된 정보만 존재함 | 과거 선정 근거로 인정하지 않으며 확인 불가 처리 |
| 기준일에 상장, 이후 상장폐지 | 초기 모집단에서 사후 삭제하지 않음 |
| 현재 목록만 있고 기준일 구성 증거가 없음 | 과거 전체 시장 재구성으로 검증 완료 처리하지 않음 |
| ETF·ETN / 종목 유형 불명 | 각각 확인된 제외 / 확인 불가, 일반 주식으로 추정하지 않음 |
| 확인된 0 거래대금 / 거래대금 누락 | 각각 N개 평균에 0 포함 / 확인 불가, 같은 값으로 대체하지 않음 |
| 실제 거래대금 없이 OHLCV만 존재 | 종가 × 거래량을 실제 거래대금으로 대입하지 않음 |
| 기준일까지 필요한 실제 이력이 부족함 | 선행 이력 부족 사유 보존 |
| 저장 이력만 부족하여 실제 자격을 모름 | 자격 미달과 구분하고 보충 가능성·출처 확인 |
| 선정 후 평가 일봉이나 다음 시가가 없음 | 후보 유지, 실험 실패·불완전 보존, 조용한 삭제·대체 금지 |
| 결과가 손실 또는 무거래임 | 후보와 결과를 그대로 보존 |
| 원본 중복·시장 충돌·잘못된 기준·해시 변화 | 입력 검증 실패, 기존 증거 덮어쓰기 금지 |

확장 평가에서는 청산비용 반영 수익률, MDD, 완료 거래 수, 이익 집중도, 무거래 비율과 자금 노출을 시장·기간별로 함께 비교한다. 동일 종목 보유 비교도 같은 비용을 사용한다. 서로 독립적인 종목 결과를 공유 현금 계좌 수익률로 합치거나 수익률 하나로 전략을 승격하지 않는다.

이미 확인한 기간과 종목은 미사용 구간으로 재지정하지 않는다. 실제 미사용 기간·Walk-Forward·모의투자 실행의 통과 기준은 별도 계획에서 결과 확인 전에 정해야 하며 이번 문서가 이를 대신하지 않는다.

## 완료 범위와 남은 준비

이번 문서의 완료 기준은 선정 입력·시점·정렬·실패·증거 계약과 현재 구현의 차이가 명확하고, 같은 기준일·원본·설정으로 같은 후보를 재현할 방법을 설명할 수 있는 것이다. 후보 수를 늘리거나 수익성 검증을 완료한 것으로 계산하지 않는다.

현재 남은 준비는 기준 시점의 종목 구성·유형·상장 상태 원천 확인, 실제 거래대금과 시점 정보의 확보, 실험별 숫자 기준 확정, 원본 보존 및 선정 계산·검증 구현이다. 전체 시장을 무제한 조회하는 Broker 호출, Redis 등 인프라 추가나 운영 후보 확대는 이 계약만으로 허용하지 않는다. 수집 범위·예산과 실패 정책은 별도 구현 전에 확정한다.

과거 모집단과 기업행위 자료를 확보할 수 없다면 그 한계를 공개한 고정 표본 연구와 향후 시점부터 수집하는 모의투자 검증을 구분한다. 이 계약 자체는 수익을 보장하거나 실제 주문 권한·자금 한도를 확대하지 않는다.
